## Exactly one authoritative expectation

The existing package projection emits a prospective template with a null ledger
hash; the finalizer emits the authoritative complete current-ledger expectation.
The selector requires exactly one non-null candidate, the unchanged version-one
schema and exact active roster/current ledger hash, retaining held/rejected rows.
Every null template must match that entire finalized body except the null hash.
It must also have the fixed package intent/config and whole-file preparation
receipt, bound to the actual selected registry, original issued-plan ledger and
current rebind. Missing, forged, contradictory, consumed or packaged preparation
metadata refuses selection. These are structural byte/role bindings, not a claim
that candidate receipts independently authenticate an execution.

No path-name precedence chooses an expectation. Duplicate authoritative candidates
and wrong current bindings retain full CI. The final smoke receives only the
unique current-bound path, never the null template.

## Narrow inert and native roles

Within authenticated retained ownership, README.md and CHECKPOINT.md plus ordinary
text diagnostics must be valid bounded UTF-8 without NUL, and remain outside all
consumed and packaged roles. Configuration-like requirements/constraints text,
unknown Markdown, new executable code, foreign paths, rename origins, nonordinary
modes and oversized members retain full fallback.

Native operands may live under the authenticated retained scope, but only exact
rows/runs binary basenames pass the prefilter. Eligibility still requires the
fixed native request/facts/manifest role, exact basename/descriptor identity,
complete unchanged containing-fragment custody, inverse ranges and encoded hash.
An unconsumed binary or a coherently rebound wrong role is not eligible.
