## Stage A: smallest reusable positive interface

1. Add one explicitly versioned dated-centre support member to the existing source-target evidence input. Proposed names are design placeholders, not an implemented schema. A v2 source-evidence variant can add an immutable `dated_centre_support` locator while retaining all v1 whole-source/physical/native inputs. Its absence follows the unchanged v1 path. Do not add case/owner-specific policy switches, a second constructor, an image classifier or a new authority registry.

2. That member must authenticate the actual adopted interpretation and its underlying evidence, not accept `reviewed: true`, a category label, an issue-comment URL, caller-written hashes or a hand-picked list as sufficient support. Bind immutable commit/path bodies and their existing whole-byte descriptors for: the original full source record and array index; exact original owner/y/x and unchanged binary64 centre; original target/source IDs and source vintage/purpose; dated scene identity and sensing time; the actual frame/window/centre registration and preserved observation/method output; substantive independent interpretation and adopting record. Reuse shared scene/frame bodies rather than repeat them per key. Local paths and signed retrieval URLs are not immutable identity. A hash proves custody, while the independent scientific review establishes the bounded interpretation's meaning.

   **Actual custody boundary:** the published Vân Đồn132-file packet contains complete point observations/reviews/adoption and96 unmarked native RGB/NIR PNGs. Its large first-date raw TIFFs/masks remain local; published hashes do not make those bodies immutably available. The Cát Hải55-file packet has the analogous distinction, plus the tiny two-key TIFF. The implementation must name exactly which provenance bodies it actually consumes. Published observations + native PNGs + review/adoption may supply the input only if the scientific policy explicitly accepts this retained-interpretation route; it cannot silently claim raw-raster replay/authentication. If that policy instead requires reading the large raw TIFF/mask bodies, their missing durable immutable custody is the precise blocker. Do not automatically reacquire, rerun, or claim a published raw-body locator from a hash alone.

3. Only exact records whose adopted claim positively locates the unchanged centre on a terrestrial body can provide this new support. Preserve its original wording and limits: it is native-centre land-location support, not whole-cell dryland, dry understory, a universal land-cover class, legal coastline, territorial title, or present-day land. Dated water, unresolved shoreline/cloud/mixed margins, mere scene-footprint coverage, WorldCover class agreement and generic question completion provide no positive land support. A mixed/managed/coastal category is not automatically accepted or rejected by its name: the actual adopted per-key interpretation must supply the required centre-location claim. Temporal/registration ambiguity remains a hold. No new blanket positional threshold or legal clearance gate is invented.

4. Extend the existing positive coverage input of `deriveSourceTargetNativeDelta` with exact keyed native-centre rows, associated with the same original `source_id` and target owner as polygon coverage. The authority function authenticates/reconciles those rows before passing them to the existing source/coverage decision. Rows may compact adjacent accepted keys only when their support/provenance is retained exactly; they cannot fill gaps. Require the proposed patch to be a subset of those supported exact keys in this mode. Do not turn pixels/centres into synthetic polygons, buffer shores, borrow sibling coverage, or replace the original base geometry.

5. Keep the source polygon scan, competitor-owner set, source-ID/owner reconciliation and boundary ordering. A point-supported key still needs an active matching original source member; it does not escape original-domain, competitor, hole, tie or territorial checks. Because dated-only support has no coverage polygon, the existing competitor prefilter must use the complete retained selected-source/base bounds as a conservative search domain, rather than an empty or invented land polygon. Whole original source products remain consumed and rejoined. Point support adds exact cuts/coverage spans only; it does not modify the source geometry/scanner.

6. Keep `reconstructionResidualPointsets` and its negative accumulation/scan/veto unchanged in Stage A. Preserve all original physical supports, query completeness, issues, exterior context, measured siblings and land/water class partitions. Existing mapped-water support cannot be relabelled dated land or borrowed as such. An actual conflicting water interpretation cannot enter the positive set. No new support member licenses discarding a relevant negative contact, tie or unknown. The complete constructor either qualifies the exact proposed patch or refuses it; do not catch refusal and emit authority for a trimmed remainder.

7. Retain the existing native-only ledger/component, rule preimage, registry and patch formats. The source-evidence hash already binds the new member and its adopted semantics through the authority rule, while `source_receipt_sha256` continues to identify the original physical report. Do not rewrite it to imply that the old map contains new land. Check any closed input-role descriptor/read inventory for the added immutable member with the resource-accounting owner; no parallel authority-lifetime rewrite belongs in this work.

Expected production touch surface: the source-evidence reader/positive assembly in the selected-neighbor module and the existing positive-coverage seam in `src/native-grid.js`, plus focused tests. Delivery readers/preparation require changes only if a concrete closed role contract needs the new member. No change is presently justified in negative witness handling, native component/browser patch shape, authority lifetime, current-bank conservation, or source providers.

## First execution and conditional Stage B

After implementation and independent review, the parent supplies immutable accepted evidence and the exact source-compatible 1,977 candidate keys, obtains normal admission and invokes the **ordinary constructor first**. A successful result still requires normal current owner-zero, selection/conservation, retained native readback and delivery checks. No qualification or repair credit is anticipated here.

Only after an actual refusal, and only when a partition is needed to understand it, use the existing diagnostic interface. Preserve the real first predicate and complete requested-key partition. If it proves an exterior-context boundary relevant to an otherwise supported key, obtain a separate independent scientific/policy decision before proposing Stage B.

The potential Stage B seam is precise but **not authorized implementation in this plan**: `reconstructionResidualPointsets` retains operation roles in `result.support` / `issues.reason`, then returns bare geometries at 596, 621 and 624; the selected-target and measured-sibling consumers flatten these into owner veto geometry arrays, and the scan combines all hits into `residualHits`. Typed role preservation would have to change that return and both consumers/accumulators/scan. It must distinguish old mapped-L1 exterior context (absence from that retained map, not proof of real water) from explicit missing/extra reconstruction, contradiction and hierarchy witnesses. The latter are retained operator/conflict facts and remain unconditional vetoes under this scope. Old exterior also remains an unconditional veto in Stage A. No exterior exception follows automatically from a land-location answer or map disagreement, and no blanket water/exterior/conflict bypass is proposed.

## Focused implementation and independent review

Reuse the existing `test/native-witness-authority.test.mjs`, `test/source-target-native-delivery.test.mjs` and `test/source-target-native-diagnostic.test.mjs` fixtures and real constructor entry. Add only tests for the new semantic behavior:

- One source-compatible exact dated-centre positive, absent from mapped positive support but with no negative contact, qualifies; an adjacent unreviewed key does not. Its native component/patch has exactly the authorized keys and retains the bounded claim through authenticated source evidence.
- Wrong original key/centre/source member/owner, changed scene/frame/observation/review body, missing adoption, duplicate/gapped class rows, unknown interpretation and water-only/unresolved evidence refuse. A review boolean by itself refuses. Same-owner sibling coverage still cannot be borrowed.
- The same otherwise positive dated key still refuses each existing source-domain, competing owner, territorial, current-owner and boundary-tie case. Actual missing/extra, contradiction/hierarchy and exterior witness contact each veto it, including an unselected measured sibling. Keep the existing exterior tests at native-witness-authority 125, 147–152 and diagnostic 121–134; do not weaken their assertions to make the new route pass.
- Existing mapped land/inland-water routes, class borrowing failures and complete diagnostic supported/held conservation remain unchanged. Unknown whole query/witness input aborts rather than producing a partial authority. Current owner-zero and actual additive application/readback preserve all predecessor assignments with zero removed/reassigned cells.

The independent reviewer should inspect the actual semantic diff and exact first candidate's evidence, rather than accept fixture green status as scientific proof. Check especially that no post-hoc boolean, missing coverage geometry, failed witness scan or absent class causes a fail-open branch; raw image support is not inferred from metadata. Review the actual ordinary-constructor result before any optional diagnostic or negative-policy proposal. Run focused affected tests on the accepted implementation environment; this planning task ran no tests or operators and requests no broad rerun.
