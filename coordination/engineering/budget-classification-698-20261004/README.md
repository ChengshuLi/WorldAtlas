# Deployment budget applicability

The classifier executes only from the pull request base or the main push before commit with a read-only token. Candidate classification code cannot authorize its own package skip. Missing trusted code or inventory errors select full packaging.

Pull requests exhaust file pages, compare their count to metadata, include renamed/copied source paths and recheck the head after enumeration. Push comparisons require valid before/after commits, complete files below the API cap and a matching comparison head. Unknown paths require full packaging. The explicit package-independent list covers named coordination scripts/tests/workflows, plain Markdown/text documentation and engineering JSON/log/text receipts. The deployment budget workflow and classifier changes always require full packaging.

The focused package job checks out only six unit-test inputs. It installs no dependencies and restores no dependency cache. Both profiles run the original archive accounting and reserve tests plus the classifier controls. Full packaging retains the original Python/Node installations, hosted build and file/archive accounting artifact. Classification publishes a separate applicability artifact; the focused summary makes no current package-size claim.

The original hosted package metadata is retained without modification. Its timing is one observation on a hosted runner.
