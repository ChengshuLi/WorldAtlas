# Joint selected-geography checkpoint consumer

This change activates no geographic release and changes no scientific predicate.
It connects the authenticated append transition to the actual native comparison
and complete continuous operand consumer in one trusted Node invocation.

## Execution and authority

`selected-joint-entry.mjs` authenticates its complete actual executing code before
imports, bootstraps the installed runtime once, and qualifies one checkpoint and
one transition. Both consumers receive the same private transition and exact
budget object. `authenticateTransition` rejects caller-created wrappers even when
they contain genuine state handles. The joint owner releases the entire session
in `finally`, including every error and fallback.

The native consumer owns native interval semantics. The continuous consumer uses
the transition's complete old-and-new affected-neighbor closure, reads original
whole features for that closure, and explicitly reuses those identical source
pointsets for the candidate. It joins actual feature IDs to their whole-feature
and geometry inverses rather than treating request order as source order. Each
vintage retains its complete literal addition roster.

The original Python publication readback and strict polygon comparison now live
in one function called by both launch routes. Their actual coverage and overlap
predicates are unchanged. The original cold Node entry is unchanged. A missing
checkpoint or unsupported candidate returns an explicit cold decision; the
wrapper then performs the original cold native and continuous checks. The
one-candidate cold admission bridge is not implemented or claimed here.

The shared qualifier accounts for its complete retained state and source/native
projections. The joint caller separately admits its code, runtime identities and
native report. The continuous consumer reserves the original output bound with
the qualifier's conservative JSON representation allowance before projecting any
source. Output caps are unchanged. Publication checks the entire encoded/decoded
operand, fact and receipt union before writing, rejects existing and symlink
outputs, and writes the completion receipt last.

## Verification and current limits

The consumer tests use an ordinary committed miniature trusted Git repository
and real checkpoint/transition/projection APIs. They cover private authority,
full identity joins, carry admission, expiration, honest fallback and actual CLI
output/code rejection. The Python tests run the actual polygon/readback code for
literal additions, overlap with unchanged neighbors, competing changed owners,
coverage loss and altered scopes/products. Separate routing probes establish
that the normal wrapper does not launch duplicate old children on joint success.
Synthetic controls do not establish real selected geographic equivalence.

This implementation is being developed against the reviewed shared module from
PR #1782 and the native consumer owned by PR #1783. The diagnostic branch carries
those unmerged dependencies explicitly. The integrated genuine retained-input
comparison, final native API, exact combined code profiles, independent review
and normal integration remain pending. No complete-path timing or zero-load
scientific execution is claimed by these focused controls.
