# Receiving-metadata computation reuse

Issue #1793, first bounded increment: avoid repeating a successful trusted PR
geography computation when a direct successor changes only its receiving README
and/or evidence manifest and the existing audited input collector proves every
actual scientific route unchanged. Full regressions and their package build are
still executed. This is not an end-to-end latency claim.

PR #1790's direct successor b1cc388a9489385314d3282768eb9e850da37cf8
changes only its packet README and evidence-quality.json above

The changed receiving manifest and README are real current evidence inputs.
Their exact-head evidence gate and substantive review must run again. Package
materialization uses a separate declared source image; these two files are not

specific unchanged catalogue/helper and fixture roles, but arbitrary full-test
inputs do not yet have a sufficiently bounded automated reuse contract. That
remaining issue is not hidden by classifying filenames as documentation.

## Trust and applicability

- Read the live PR/issue, exact direct parent, complete nontruncated Git trees,
  ordinary file modes and authenticated bounded metadata bodies. Only the
  issue-declared branch-matched receiving manifest and packet-root README can
  differ. Added/deleted/renamed files, extra leaves, package inputs, executable
  metadata and symlinks decline reuse.
- Authenticate the exact completed original run and unique successful geography
  job and steps. Failed scope/evidence does not invalidate that successful
  computation; it also never supplies current authority. The original producer
  workflow must match the trusted event baseline. Historical mutable embedded
  PR heads are not substituted for the immutable run/job head.
- Use the existing authenticated original log/upload/archive/report reader.
  Require the exact same trusted baseline, original candidate, ordinary passed
  report and no source-adjudication exception. Missing/changed provenance or
  artifacts falls back. No original report is rewritten or uploaded as a new
  execution.
- Run the existing audited selected-input collector on original/current heads,
  with the original trusted reader policy. Its new receiving-metadata scope
  option changes admission only. All execution-code, selected current,
  historical, strict-origin and fallback-presence bindings still must match.
  A metadata file actually consumed in any audited route rejects reuse.
- Reread current PR/issue and original run attempt before success. Keep profile,
  scope, ownership, evidence and exact-head review fresh. The bounded optional
  discovery falls back to the normal geography checker on failure or timeout.

Only geography-reuse.json is emitted for reuse, with the original source identity
and the current applicability decision. The original scientific checker step is
skipped, so successfulGeographyJob deliberately grants no transferable producer
proof to this new job. The normal merge queue performs its one exact-candidate
geography check. #1788's accepted checkpoint root/member custody remains unchanged.

## Verification and remaining work

Focused tests cover actual immutable-tree changes, malformed metadata, consumed
package roles, failed/ambiguous producer jobs, altered original report/baseline,
source artifact refusal, changed attempts and current-authority drift. Collector
tests use actual tiny Git histories and nonvacuous current/historical/fallback
roles through both allowed receiving filenames; they do not rerun science.

Hosted activation depends on the geography job's read-only Actions permission
owned by #1788 and rebasing onto its accepted workflow. Current PR and queue
science are never cancelled to activate this increment. Full-regression/build
reuse, real subsequent hosted adoption and measured critical-path reduction
remain open on #1793. No source approval, live import or publication is granted.

Independent review found and corrected a producer-log compatibility defect:
ordinary fresh jobs must retain only their original geography artifact, because
the existing authenticated receipt parser requires one unambiguous upload digest.
The separate equivalence artifact is therefore uploaded only on successful reuse.
A real-format one-upload positive/two-upload negative control guards that boundary.
Independent review also matched all retained replay descriptors against their
pinned Git trees. Process-group cleanup on an inner Git timeout remains unexecuted;
the outer workflow deadline is bounded, but no orphan-free claim is made. Issue
contracts using a literal branch-matched manifest path are supported; templated
manifest paths conservatively fall back to fresh geography in this increment.

## Bounded regression continuation measurement

The four identified real-checkout controls (job-deadline, supported-programs,
selected-data-profile and integration-profile-restoration) passed all 240 tests
with zero skips in 52.514 seconds on accepted04c consumer versions, invoked
directly with `node --test --test-concurrency=2`. The report and compressed
complete output are retained beside this README. No full-profile setup, package
build or native/polygon computation ran. Test peak RSS was 544,032 KiB.

This is warm-fixture test time, not setup or hosted critical-path time. A large
one-time batch restored 614,655,083 bytes of exact retained fixture bodies in
107.101 seconds, with 214,836 KiB peak import RSS; other small setup batches are
not included in that import duration. The complete setup is not claimed as a
single measured operation. All restored bodies remain local and reusable.

Future regression reuse needs a bounded known-programme matcher in addition to
the predecessor/successor input comparison. Ordinary checkout/package import
closures do not include all discovered tests, spawned helpers, extracted-code
`new Function`/VM routes or the archived original validator. Their exact audited
memberships must be included, using existing original inventories where present.
Unknown readers fall back. The successful predecessor can bind changed scientific
data, while current metadata/HEAD controls run fresh; programme identity must not
silently expand to arbitrary new test or helper code. #1794 still enables only
geography reuse; this measurement supports the next #1793 increment.
