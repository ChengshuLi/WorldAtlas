# Wheel zoom #886

The native Leaflet wheel handler debounces input and issues discrete animated camera changes. Repeated wheel events can arrive while a previous animation is active, losing most of the intended travel. The new controller accumulates pixel/line/page input into a clamped fractional camera target, follows it with one animation-frame loop, preserves the pointer anchor, and discards outstanding momentum on reversal or external camera movement. It leaves browser Ctrl/Meta zoom gestures alone. Its integration uses the same private Leaflet 1.9.4 camera primitives as that version's TouchZoom; recheck this adapter when updating Leaflet.

WebGL immediately transforms the cached image and coalesces camera-only draws into one pending frame. The existing canonical ownership textures, styles and metadata remain separate; navigation does not recompile or upload ownership. Drawing newly exposed areas and maintaining screen-width borders still requires inexpensive GPU work. Canvas uses cached image transforms, a bounded refresh during zoom-out and a final detailed repaint. Its worker results are invalidated when the camera moves. Neither path changes canonical grid precision, location identity, dataset generation, evidence, dated facts, roles, credentials or storage.

`targets.json` gives the numeric aims and conditions chosen after initial baseline/trials and before final candidate acceptance. All raw samples, traces and screenshots remain retained. The `live-before`, `live-metal-before`, `eu5-before`, `local-per-frame-trial`, `local-cached-trial`, `local-metal-after` and `local-metal-range-trial` files are earlier observations/prototypes, not final source or deployment acceptance. The cached-image-only trial was abandoned because zoom-out exposes areas outside that image. The early `live-metal-final-before` range-out follows its actual range-in endpoint, rather than starting at maximum; do not treat that row as a maximum-to-minimum baseline. Final matched measurements use explicit button setup for both endpoints.

The browser starts a separate Playwright headless process/context with no user profile. Default Chromium uses SwiftShader on this machine; `ATLAS_BENCH_ANGLE=metal` explicitly selects the Apple M1 GPU. Retain the software GPU misses: its repeated WebGL camera draws miss the native-GPU frame target. Metal results do not erase them or establish universal performance. The Canvas fallback's occasional CPU paint can also miss the native-GPU target. Compare EU5 only on matching browser/GPU/input conditions; it has no comparable Leaflet CSS-frame latency proxy, and successive samples do not reset its camera. Its frame timing is an observational reference, not an implementation, historical-data or travel-range certificate.

The first changed canvas/pane transform or draw is an observable browser-work proxy; it is not photon latency. rAF gaps include wheel delivery and settling. Synthetic trusted Playwright wheel input is not a physical mouse/trackpad certificate. Positive/negative timing vectors check arithmetic and reject unchanged/no-input false responses. Original full observations, target misses, frame gaps, tasks, draw calls, downloads and ownership counters are in each JSON/trace. Source and provider pins remain separate from candidate local builds.

Reproduce with Node 24 and the lockfile dependencies. Install a separate headless browser with `PLAYWRIGHT_BROWSERS_PATH=/absolute/owned/cache node node_modules/playwright/cli.js install chromium --only-shell`; never attach to a user's browser. Run `node scripts/preview-wheel-zoom.mjs` in this checkout for a localhost source build that proxies only public GET assets/APIs. It does not seed a database or regenerate data. Run `ATLAS_BENCH_ANGLE=metal node scripts/benchmark-wheel-zoom.mjs URL OUTPUT.json` for macOS native-GPU samples. Use `ATLAS_BENCH_CANVAS=1` to force Canvas. `node test/wheel-browser.mjs` creates an isolated local fixture; `node scripts/verify-wheel-app.mjs URL OUTPUT.json` checks all modes, year races and inspector/picking against the current data. Run `node --test test/wheel-*.test.mjs` and `node scripts/check-wheel-measurement.mjs coordination/engineering/wheel-zoom-886` for timing/input controls.
