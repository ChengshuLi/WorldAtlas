# Admitted processing budgets

Refs #1745. Processing resources are execution configuration, not scientific method. This change removes the duplicated 256 MiB logical / 8 MiB output ceilings in current rebind execution and separates historical producer evidence from current readback admission. Historical request, facts, operating receipt, result identity and scientific predicates remain authenticated against their literal issued limits. Whole-member/decompression limits, descriptor bounds, fresh destinations and owned-process cleanup remain enforced.

## Configuration and actual admission

The rebind template's `limits` may be `"auto"` (or absent), or an explicit object with positive safe-integer `complete_phase_bytes`, `descriptors`, `output_bytes`, `rss_bytes`, `sampled_stop_bytes`, and `wall_seconds`. Optional `stdout_bytes`, `stderr_bytes` and `monitor_bytes` configure runtime logging; absent historical fields retain their original defaults. Each log remains subject to the 32 MiB whole-member security bound. Descriptor count remains at most 512; sampled stop cannot exceed the RSS allowance. The issuer records a fresh concrete plan without rewriting its template. The supervisor authenticates that exact plan, rechecks fresh RAM/disk, and passes its limits through the real entry, reader, product writer and terminal checks. Changing supported finite values needs no code or catalogue change.

Automatic sizing reserves half the measured residual after the coordinator's active concurrent reservations, 2 GiB parent headroom and 768 MiB margin. Its 32 MiB output, 4 MiB monitoring log and 1200-second wall values are defaults, not maxima; explicit admitted values can differ. Retained-output admission includes the configured logs and metadata overhead. Linux admission checks exposed ancestor cgroups and process limits without swap credit. The runtime observation records unavailable ancestor constraints. The coordinator must serialize admission and set `WORLDATLAS_CONCURRENT_RESERVED_BYTES`; this is cooperative protection, not an atomic scheduler or global kernel quota.

Current readers use a separate machine-admitted allowance. CI native and continuous entry points obtain it at bootstrap; nested readers inherit it. Readback charges the actual authenticated four-product union against that current allowance rather than using an old producer grant. Per-phase actual RSS checks supplement external supervisors. Completed serialization restores its caller's output reserve on both success and refusal, preserving the measured peak; returned live data remains charged as metadata.

The package publication copy inherits its parent reader's allowance. Assembly's issued execution profile must flow through outer pre-use, child reader, output/retention checks and final summary; its current control values are configuration, not replacement hard ceilings.

Disk reservations are cooperative growth estimates, not per-checkout quotas. The supervisor verifies the exact owned ready slot and its measured footprint, charges outstanding peer reservations plus current issued growth, and preserves the allocator's fresh free-space floor. It does not edit the allocator registry or reject already-materialized data merely because it exceeded an old reservation.

New SOURCE/NATIVE requests use `source-native-v2`, an explicit `processing_allowance` (`phaseBytes`, `rssBytes`), `output_reserve`, and finite issued `operating_limits` for process RSS, wall time, products, retained storage, stdout, stderr and monitor data. Legacy v1 evidence retains its literal historical interpretation. Native/context preparation accepts the same current allowance and rechecks live supply. Existing input acquisition ordering is unchanged; this does not claim a new complete pre-read input-union proof. The retained chained-context guard compatibility is an exact authenticated old/new whole-body pair, preserving all non-budget asset and output helpers.
