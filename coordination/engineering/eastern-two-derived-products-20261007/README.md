## Reproduction and downstream use

Use the pinned Python 3.12 interpreter and Node 24. All declared historical Git
objects must be available locally; fetch the exact original commits if creating
a new clone. Run from the repository root, with the actual immutable delivery
commit in place of `COMMIT` and the exact Node executable recorded in
`runtime-guard.json`. The Python executable must resolve to the same authenticated
Python binary and runtime module tree. A different runtime needs its own truthful
reviewed execution capsule; passing a version string alone is insufficient:

```sh
python coordination/engineering/eastern-two-derived-products-20261007/controls.py
python coordination/engineering/eastern-two-derived-products-20261007/semantic_controls.py
python coordination/engineering/eastern-two-derived-products-20261007/guard_controls.py /exact/authenticated/node
python coordination/engineering/eastern-two-derived-products-20261007/verify.py \
  --commit COMMIT --destination .cache/1386-first --node /absolute/node24
python coordination/engineering/eastern-two-derived-products-20261007/verify.py \
  --commit COMMIT --destination .cache/1386-second --node /absolute/node24 \
  --identical-prior .cache/1386-first
```

The optional prior path saves disk only after each freshly decoded complete
member is compared byte-for-byte. It does not skip source restoration, semantic
consumers or evidence checks. All resulting ordinary files remain accessible
in both trees, without symlinks. Child outputs are under
`full_ownership_products180`, `full_runtime_products55` and
`full_pixel_products2`; the parent may consume these complete products after
actual reviewed merge. It must still complete atomic v8 activation and the
normal offline package build. #1295 and the global #1202 goal remain open.
