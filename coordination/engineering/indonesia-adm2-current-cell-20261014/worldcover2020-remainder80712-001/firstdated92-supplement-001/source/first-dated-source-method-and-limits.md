## Radiometric contract and unresolved baseline05 contradiction

The actual selected headers report GDAL scales1/offset0 and no embedded band scale/offset tags. They must not be interpreted as proof that nativeDN already equals physical reflectance or that a source offset was applied.685 selected points use baseline02.13/02.14 items with `earthsearch:boa_offset_applied=false`, declared reflectance scale0.0001 and offset0. Their declared derivation, if later authorized, is DN×0.0001; the additive baseline04+ change does not apply to these baseline02 products. Raw data/masks remain unchanged.

The other93 points are Batam baseline05.00 items with `earthsearch:boa_offset_applied=true` but declared asset offset−0.1. This is a documented provider-metadata conflict. Current [official collection notes](https://github.com/Element84/earth-search/blob/main/docs/collections/sentinel-2-l2a.md) direct use of nonzero asset offset after scale. In the provider's [official issue9](https://github.com/Element84/earth-search/issues/9), maintainers explain that legacy offset metadata can be stale when the offset has already been applied, and that old COG scale/offset tags can be absent. The provider's [discussion26](https://github.com/Element84/earth-search/discussions/26) describes historical conversion that applied the additive offset into stored COG values while preserving nodata. These sources were actually retrieved and retained under provider-contract/ with response receipts and hashes.

Accordingly the plan permits only authentic rawDN+mask/SCL acquisition for these93 points, pending independent review and Root launch. It prescribes no unconditional absoluteBOA-reflectance formula, no second subtraction of−0.1, no derived index or quantitative reflectance display until the actual provider contract is resolved. Preserving raw observations allows later interpretation without re-fetch or source alteration. Provider quality percentages, a default TIFF scale or an attractive visible result cannot resolve the contradiction. This is a specific radiometric limit, not a new universal physical or legal gate.

License links in each actual item refer to the Sentinel Data Legal Notice. The plan retains those actual provider declarations and does not claim that a new license instrument or remote full-object hash was reviewed. The source-native method references are scientific mechanics only; their legacy application budget/allowance/limiter machinery is neither copied nor executed. Current work uses the existing installed Rasterio runtime without installation, custom resource policy or heap flags.

The initial automatic approval refusal and the factual single allowed reconsideration on independently proven public-coordinate evidence remain preserved in the historical metadata and public held-question packet. That proof was not sent to the catalogue; the original same-action retry was allowed and completed. The subsequent coverage query is separate metadata work under Root's no-cloud-gate direction. No value window may be launched before the complete plan's distinct review and explicit Root authorization. Current scientific adoption, native-authority and repair credit are all zero.
