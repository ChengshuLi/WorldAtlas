# Venezuela interior review packet — issue #376

**Evidence vintage:** retrieved/reproduced 2026-10-06. **Review status:** bounded source and semantic assessment only. This packet does not approve any territory, region, boundary release or location-attribute import.

## Exact scope and baseline

`scope.json` is the preserved exact 188-member issue scope, with the original release/hierarchy/footprint pins. It covers 188 of 327 Venezuela area members, so it is partial by design; issue #375 owns the complementary packet and combined area decisions belong to integration. The 17 listed province IDs and exact location IDs are preserved. Current baseline mapping is checked by ID, not by name. No geometry, hierarchy, release pin or source data in the baseline was changed.

Of the 188 members, 184 are source-backed `gb:VEN:ADM2` records and four are Atlas physical fragments. The ADM2 source itself contains 335 features. Its metadata identifies the 2015 collection as `Municipios` and credits Carlos Efrain Porto Tapiquen. The Venezuelan Organic Law on Municipal Public Power, Article 2, defines the Municipio as the primary political unit in the national organization. That statement supports the intended administrative concept; it does not establish an individual unit's present-day border or completeness. Seven source names include “Autónomo”; the current source itself puts them in its Municipios collection under Amazonas. This is not a legal instrument crosswalk for each unit, so their specific Indigenous governance and land demarcation relationships remain open.

## Method and per-location evidence

From the repository root, run `sh data/regional-review/regional-review-920c7b12f5777da1/restore_inputs.sh igvsb` only when current use terms permit local inspection. It downloads to the packet source directory and refuses bytes that do not match the recorded SHA-256; the archive is intentionally untracked and must be removed after use. Install the pinned requirements into the packet-local scratch directory (after the repository storage check) with `python3 -m pip install --target data/regional-review/regional-review-920c7b12f5777da1/.scratch -r data/regional-review/regional-review-920c7b12f5777da1/requirements-reproduction.txt`, then run `PYTHONPATH=data/regional-review/regional-review-920c7b12f5777da1/.scratch python3 data/regional-review/regional-review-920c7b12f5777da1/reproduce_assessment.py`. It reads the pinned baseline by exact IDs and emits `findings/location-assessments.jsonl`, `.csv`, `assessment-summary.json`, `physical-subdivision-summary.json` and `granularity-screen.json`. It does not write outside this packet. `verify_packet.py` checks scope identity, per-member cardinality/classifications and every retained input hash; it does not replace the geographic reproduction. Remove `.scratch` and the restored archive/PDF after reproduction so only evidence authorized for retention is committed.

The screen reconciles each source role/name/vintage, maps its Atlas parent to the 2020 ADM1 reference and computes a comparative planar WGS84 overlay, compares normalized names to the 2016 IGVSB municipality rows, records same-name polygon overlap ratios, and intersects the source municipality against IGVSB features whose names begin `Zona`. It reports conflicts when planar intersection area is at least 0.0001 of that ADM2 geometry. These geographic-coordinate area ratios are screening diagnostics, not geodetic measurements, cadastral proof, legal evidence or a verdict on which party's line is correct. A missing name match can reflect naming/vintage changes as well as a genuine source gap.

The reproduced outcomes are 152 `justified`, 35 `insufficient-evidence`, and 1 `correction-needed`: the insufficient group contains 31 administrative rows and the four physical fragments. Of the 31 administrative rows, 24 have a normalized-name comparison but fall below the explicit 0.98 2015-to-2020 parent-containment screen, while 7 lack an exact normalized name match in the 2016 comparator. Separately, 35 administrative rows intersect at least one named `Zona` feature: 31 are role/parent-justified only and 4 are insufficient; all 35 keep boundary status open. The archive contains 65 named overlap-zone features and 4 no-jurisdiction features. The row file names every intersecting feature and its fraction. No one is instructed to move a boundary based on this screen.

Four physical labels (`atlas:physical:432b44d2e7bdcbd1a570`, `atlas:physical:5f7ea253b110fb6890e9`, `atlas:physical:736a88b00fc9541855f2`, `atlas:physical:cc53a89e1f220c7c9194`) resolve respectively to RESOLVE 2017 IDs 490, 572, 464, 466 and all back to the same source feature, Municipio Raúl Leoni. ## Granularity, omissions, and neighboring comparison

Municipios are the source's municipal administrative unit; the packet does not interpret cities as municipalities. Caracas-area names remain municipal records or administrative fragments in this source, not sourced urban-settlement polygons. No parish (parroquia) boundary collection is included, so no parish-level tier or city boundary is inferred. The scope contains an explicit disputed-area pseudo-unit and four ecology-derived fragments; the classifications identify these as unlike ordinary Municipio rows. Seven source labels use “Autónomo”; they map to Amazonas in this pinned source and remain ordinary Municipio collection members for this limited screen. The source itself does not provide an enacted local instrument or Indigenous territorial-demarcation crosswalk for these names. Do not treat the label or large area as proof of a particular traditional territory; retain their administrative role at the source collection level and leave the local status for follow-up. Review at 2020 ADM1 parent scale uses the separate 25-feature collection. Province/municipality counts are inventory checks only.

Completeness is unresolved at every larger level: the comparison source is 2016, geoBoundaries ADM2 is 2015, ADM1 is 2020, and the issue owns only part of Venezuela. The IGVSB layer includes separately named overlapping/no-jurisdiction zones, but there is no independent modern legal/cadastral edge evidence here. Four scoped polygons are multipart (San Joaquín 2 components, Carlos Arvelo 6, Zamora 4, Fernando de Peñalver 2); component-area fractions are in `findings/granularity-screen.json`. These deserve component-to-current-register review, particularly coastal/island component checking, but their multipart encoding alone does not identify a missing territory. Ten source municipalities cover at least 25% of their matched ADM1 parent in the rough WGS84 screen; see the same output. This flags very large municipality-scale units, not a size error or proof of province-tier status. The packet has no city/urban extent polygons, so city fragmentation cannot be judged from municipal geometry alone. Island, detached-area, anonymous remainder, and urban-settlement completeness cannot be established from this limited collection. Specifically, the cited source set does not supply a complete islands/keys/coastal feature inventory; no absence conclusion is made. For neighboring scope, use issue #375's separate packet and the pinned complete region handoff; do not combine or certify the region from #376 alone.
