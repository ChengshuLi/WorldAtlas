# Serbia #1017 register packet preservation erratum

Research completed 2026-10-06 (America/Los_Angeles), issue #1186. This packet adds a safe reproducer under its declared owned prefix. It does not replace or edit the historical #1017/#998 sources or outputs, and it does not certify Serbia's administrative boundaries.

## Scope and reproduced findings

The captured #1186 machine contract fixes 67 ordered `gb:SRB:ADM2` IDs and the one owned prefix. The reproducer verifies the issue contract and its canonical subject-list SHA-256 before output, checks the retained source pins and five original output hashes, and joins each of the 67 IDs against the pinned source ledger, geoBoundaries feature identity and `data/geography/part-22.json` name/parent. It reproduces the four historical generated products byte-for-byte: the subject crosswalk, 12-parent roster comparison, nine-row urban-municipality context and summary. The strengthened controls are additive; the original #1017 `validation/controls.json` is checked by hash and retained unchanged.

The compared register attributes remain limited to names, codes, administrative type and parent codes. The current 2026-10-05 SORS workbook does not declare a reference date. The 2017 workbook is dated 2017-12-31. The retained geoBoundaries file contains 145 ADM2 features, including the 67 current subjects and the disjoint 78-subject #998 cohort; its source metadata says boundary year 2017, source update 2023-01-19 and build 2023-12-12. None of those facts proves legal/effective dates or polygon equivalence. Pirot and Vršac's Atlas “Municipality” suffixes are not treated as proof of their register type; Bor and Prokuplje's 2018 register role change is recorded in the earlier source packet and remains a sourced follow-up, not an ID/name edit here.

The exact parent purpose in the retained hierarchy is the administrative district used by the SORS roster comparison. The 12 code rosters agree for these 67 scoped children. Nine SORS urban-municipality rows below city-level units are adjacent-granularity context only; they are not extra Atlas subjects and are not treated as missing ADM2 children. #998's 78 subject IDs have zero intersection with the 67 in this issue. These counts establish the reproduced roster relationships only, not boundary completeness or correctness.

The Bor/Braničevo/Jablanica/Nišava/Pčinja/Pirot/Podunavlje/Pomoravlje/Rasina/South Banat/Toplica/Zaječar parent identity and cross-country tier semantics continue in the already-owned hierarchy review #1018. This packet found no sourced mismatch that would justify an engineering correction or a new boundary proposal.

## Sources, vintage, completeness and rights

- **SORS 2017 register workbook** (`https://www.stat.gov.rs/media/2695/opstine-gradovi-2017.xls`): exact original bytes and normalized roster are pinned in the baseline inventory. Workbook reference date is 2017-12-31. The prior packet records SORS reproduction/sharing and commercial/noncommercial use terms with attribution and marking of changes. The terms page or a workbook-embedded license was not retained here, so that rights statement is inherited rather than independently reauthenticated.
- **SORS current-state register workbook** (`https://www.stat.gov.rs/media/412350/sifarnikgradovi-opstine-tekucestanje.xlsx`): exact original bytes, normalized roster and retrieval record are pinned; retrieved 2026-10-05, but no explicit reference/effective date is printed in the workbook. The same inherited rights caveat applies. SORS's register description says its public spatial-unit data come from RGA, which maintains the register under the 2020 law. Its page, inspected 2026-10-06, also reports one 2025 territorial change at settlement, municipality/city-municipality or city level. This reinforces that an undated current workbook cannot establish each unit's effective boundary date.
- **geoBoundaries SRB ADM2**, pinned release commit `9469f09592ced973a3448cf66b6100b741b64c0d`: the exact 145-feature GeoJSON and metadata are pinned. Recorded license is ODbL 1.0 with geoBoundaries and upstream-source attribution. It supplies source IDs/names and geometry type for the reproduced join, not proof of official Serbian legal boundaries. Its metadata vintage is insufficient to infer a current effective date.
- **Republic Geodetic Authority (RGA) Administrative Units Register**, `https://www.rgz.gov.rs/administrative-units-register`, inspected 2026-10-06: the official description lists unit type, name, registration code, hierarchical connection and polygon as register attributes. RGA's **EuroBoundaryMap** product page, `https://www.rgz.gov.rs/eurogeo-graphics-proizvodi-mapagranica`, describes a 1:100,000 administrative/statistical reference product. Neither webpage supplied a retained dated unit-level extract, exact release, feature completeness statement for this scope, CRS/source lineage adequate for comparison, or explicit reusable license. Web pages were inspected but not archived or hashed; treat them as restoration-only leads.
- **SORS register description**, `https://www.stat.gov.rs/en-us/oblasti/registar-prostornih-jedinica-i-gis/`, inspected 2026-10-06: describes the Spatial Units Register as public alphanumeric and geospatial data across national, autonomous, district, city/municipality, cadastral, settlement and statistical tiers, maintained by RGA. It describes register purpose/granularity; it does not expose the dated geometry needed for this issue's historical boundary question.

Source restoration remains explicit: request from RGA a 2017-12-31 and a latest dated extract for the exact 67 unit codes and 12 parent districts, including full parent rosters, type/name/code, effective dates and change history, polygons/CRS, scale/accuracy, data dictionary and source lineage, exact release ID and written reuse terms. Retain lawful original bytes, response metadata, retrieval timestamp, hashes and the license text before any feature-level comparison. No primary source is restored by this erratum.

## Reproduction, output safety and unresolved handoffs

Run twice using distinct empty output directories:

```sh
python3 data/regional-review/serbia-register-preservation-1017-erratum/reproduce.py --output-dir data/regional-review/serbia-register-preservation-1017-erratum/outputs/run-<unique-id>
```

The reproducer validates all inputs, scope and original output hashes before output. It enumerates all five output destinations before opening any, then acquires exclusive-create handles for every destination before writing bytes. A missing, duplicate or outside subject, a changed pinned input, or any pre-existing output fails closed. The negative output-control used a sentinel at the fifth destination: the command failed, created none of the first four outputs, and preserved both the sentinel and all five historical files. Fresh runs are separate; no successful run overwrites retained work.

Remaining research: obtain authenticated dated RGA extracts and their reuse grant; compare legal/effective boundary polygons and parent hierarchies against an authoritative complete neighboring roster; resolve exact current workbook vintage and the 2025 change; keep Kosovo-and-Metohija classification and other territorial-status questions separate from roster-count comparison. Geographic approval, core geography edits, import and publication remain out of scope. Engineering follow-up is needed only if an independently sourced mismatch is established; this preservation erratum does not propose a boundary correction.
