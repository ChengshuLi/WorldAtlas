# Bulgaria municipality source review — issue #417

Research date: 2026-10-05 (America/Los_Angeles). This is a read-only evidence packet for the 213 exact IDs in `source/issue-scope.json`; it neither changes geography nor certifies Bulgaria or the Southeastern Europe region.

## Finding

The source's declared tier is substantively appropriate: geoBoundaries identifies BGR ADM2 as “Municipality,” and Bulgaria's NSI says districts consist of neighbouring municipalities, while municipalities consist of one or more neighbouring settlements. The source's 2019 municipality roster can be crosswalked to NSI's EKATTE register using English municipality name plus the Atlas/EKATTE district parent name, then reporting the official EKATTE codes. All 213 scoped features find a municipality/district register match by English name and district parent name; 209 municipality names match after case/spacing normalization and four require an explicit transliteration/name alias. The Atlas parent IDs themselves are not crosswalked to EKATTE district codes in this packet. Those 213 features represent 212 unique official municipality codes because two Zlatitsa features match one code. This establishes administrative identity evidence, not the correctness of their polygons.

The all-source roster comparison is not complete: the 265 geoBoundaries features map to only 264 unique current EKATTE municipality codes. Two distinct source features named Zlatitsa (`11073933B76991292071364` and `11073933B60320132010156`) map to the one official municipality `SFO47` in Sofia district. Their retained polygons are separate single-Polygon features with non-overlapping bounding boxes. The evidence cannot establish whether these are both legitimate disconnected pieces that should be aggregated into one municipality or whether one is erroneous. Both scoped Atlas IDs therefore need their shared municipality identity resolved before either can be used as an independent municipality or joined independently to municipality-level attributes.

The only current EKATTE municipality without a source-feature candidate is Sarnitsa (`PAZ39`, district Pazardzhik). Sarnitsa is within the scope's Pazardzhik district, but it has no retained geoBoundaries feature/Atlas ID and therefore is not one of #417's 213 subject IDs. The issue scope reports 11 Pazardzhik children; NSI's 2025 district table reports 12 Pazardzhik municipalities. The mismatch is evidence of a completeness gap, not permission to add or repin subjects in this packet.

All 213 scoped source geometries are single `Polygon` features. That describes encoding only. It does not prove that boundaries are current, valid, contiguous, complete, non-overlapping or fit for the intended map. The full source contains 265 feature rows, which numerically equals NSI's 265 municipalities, but its duplicate Zlatitsa candidate and absent Sarnitsa show why equal counts do not establish completeness.

## Individual assessment

Run the reproduction to generate one local, ignored crosswalk row for every scoped source ID in `validation/bulgaria-municipality-crosswalk.csv`, plus a full-source roster audit and summary. The generated scoped rows include source name/shape ID, Atlas name and province parent, matching official codes/names, geometry type/ring/vertex counts and an assessment. The two Zlatitsa rows are `correction-needed` for a repeated representation of one registered municipality. The other 211 rows are `insufficient-evidence` for polygon correctness, although their source role and municipality-name/district-parent-name crosswalk is supported by the cited roster comparison; parent ID-to-district-code correspondence is not checked. The table does not mark a full geographic unit “justified” on the basis of an administrative match.

The four source-to-register name differences within the scope are `Dolna Mitropoliya` → NSI `Dolna Mitropolia`, `Dobrichka` → `Dobrich-selska`, `Provadiya` → `Provadia`, and `Miziya` → `Mizia`. These are crosswalk aliases; the retained 2019 spelling is not rewritten. A separate full-source table records additional name spellings and out-of-scope features.
