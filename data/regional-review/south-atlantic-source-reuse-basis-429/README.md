## Finding

The source chain contains distinct layers that the earlier #429 packet recorded together:

1. **Underlying source and vintage.** The pinned geoBoundaries USA ADM2 metadata names “United States Census Bureau, MAF/TIGER Database,” `boundaryYear: 2018`, `boundaryCanonical: Counties`, `admUnitCount: 3233`, and `boundaryLicense: Public Domain`. It also reports a source-data update date of 2023-01-19 and build date of 2023-12-12. The metadata's `licenseSource` and `boundarySourceURL` strings both contain the malformed scheme `https//` (missing `:`). The official Census 2018 archive page identifies the 2018 county 1:500,000 file and describes cartographic boundary files as simplified MAF/TIGER representations intended for small-scale thematic mapping. The exact Census ZIP and exact geoBoundaries input are retained or hash-bound below.
2. **Per-file terms.** At the pinned geoBoundaries repository commit, the project's `LICENSE` says individual data files are governed by the license(s) in each boundary's metadata. The USA ADM2 metadata says Public Domain and leaves `licenseDetail` empty. The geoBoundaries file itself defines `boundaryLicense` as the original license under which the primary source released the dataset. Thus the metadata supports Public Domain for the underlying Census file as recorded by the provider; it does not describe what rights, if any, geoBoundaries claims in its own transformed or curated contribution.
3. **Project-product attribution and derivative terms.** The same release's project `LICENSE` applies CC BY 4.0 to “computer code and derivative works generated by the geoBoundaries project.” Its product citation file separately says attribution is required for use of the product and that users of an individual boundary file should also cite the sources in that file's metadata. Current geoBoundaries API guidance describes gbOpen as CC BY 4.0 compliant and requiring attribution; that current guidance is recorded as context, not silently applied retroactively to the 2018 file.

These statements distinguish the Census source license, any project-generated derivative rights, and the provider's requested attribution. The retained primary documents do not clearly state whether geoBoundaries asserts a separate CC BY 4.0 right over any geometry transformation in this specific USA ADM2 file despite its per-file Public Domain value. The record therefore preserves that narrow uncertainty and makes no legal conclusion about copyrightability, database rights, territorial reach, or the scope of an asserted derivative. A conservative reuse handoff is to retain Census source credit, geoBoundaries product credit and URL, the exact 2018 source release, and a notice of any Atlas changes; this follows the explicit attribution requests without relabeling the source dataset CC BY.

## Scope and reproduction

The issue's exact 268 unique subject IDs are byte-for-byte the same ordered roster as the merged #429 scope. The 2018 GeoJSON has 3,233 unique `shapeID` records; all 268 scoped IDs resolve once to that source. We also retrieved the linked Census 2018 county CBF ZIP (11,530,479 bytes). Its DBF has 3,233 records; each scoped subject's source name and state have exactly one row in that Census vintage. The retained #429 assessment classifies every subject's role as counties and state parent as justified; its county-subdivision source is the neighboring lower tier. The Census CBF page says that its 1:500,000 product is simplified for small-scale thematic mapping. This is an identity/source-chain check. It does not compare polygon coordinates, establish legal boundaries, prove completeness outside the declared cohort, or infer present-day accuracy.

Run from the repository root with Python 3.12 standard library only:

```sh
python3 data/regional-review/south-atlantic-source-reuse-basis-429/reproduce.py runs/run-one.json
python3 data/regional-review/south-atlantic-source-reuse-basis-429/reproduce.py runs/run-two.json
```

The command verifies all 12 issue-pinned input files at the immutable #977 baseline, exact scope identity, retained GeoBoundaries source IDs/metadata, the Census CBF DBF record count and one-to-one name/state crosswalk for all 268 subjects. It writes deterministic, scoped output and positive/negative control evidence only in this directory. The negative control calls the same `build_crosswalk` validator with a duplicate roster, an unknown source shapeID override, and an invalid state parent; all three must be rejected. `reproducibility.json` records matching output hashes from two independent runs.

## Engineering handoff and limits

- Keep source and provider-product attribution separate in any later user-facing credit record. A suitable conservative citation is: “U.S. Census Bureau, 2018 Cartographic Boundary File, County 1:500,000; accessed through geoBoundaries USA ADM2 (2018), source commit `9469f09592ced973a3448cf66b6100b741b64c0d`; Atlas modifications, if any, are described separately.” Include links to both providers and keep the pinned per-file metadata and product terms.
- The exact metadata source URL is malformed; the official 2018 Census archive page is the actionable restoration route. The pinned geoBoundaries commit and paths are recorded in `sources/upstream-retrieval.json`.
- If engineering needs a definitive interpretation of provider-created geometry rights rather than this conservative attribution practice, request a source-owner clarification for this exact file. Do not change the original source register or replace its Public Domain statement with a blanket CC BY label.
- The source release is 2018 even though its metadata was updated in 2023. It is not a current county roster or boundary authority. The earlier #429 packet's 57 coastal boundary candidates remain the separate follow-up #975; this reuse erratum adjudicates none of them.
