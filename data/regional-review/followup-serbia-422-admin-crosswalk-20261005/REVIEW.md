# Serbia 78-subject administrative-register crosswalk

Research date: 2026-10-05. Work item: [#998](https://github.com/ChengshuLi/WorldAtlas/issues/998). Exact issue scope and baseline are retained in `source/issue-scope.json` and `source/baseline-inputs.json`; the accepted claim result is retained in `source/claim-receipt.json`.

## Result

All 78 scoped Atlas features have a unique name match in both the SORS roster marked as at 31 December 2017 and the current-state SORS Cities/Municipalities workbook retrieved 2026-10-05. Each row has a unique corresponding registration code and district/city relationship across the two rosters; the current workbook's explicit city/municipality type agrees with the Atlas label for all 78. The 2017 workbook explicitly identifies the city column but combines “municipality/city municipality/city” in its local-unit column header, so it does not provide the same explicit local type field. The 13 exact Atlas parents comprise 12 administrative districts and the City of Belgrade. For every parent, the issue's matched codes equal every primary city/municipality code in that parent in the current SORS roster: 78 of 78 scoped IDs, and 13 of 13 parent partitions, are accounted for (`sources/derived/subject-crosswalk.csv`, `parent-completeness.csv`). This completeness finding is limited to those 13 parent units and SORS's primary city/municipality roster. It does not establish completeness for all Serbia, the full OSM/Wambacher feature collection, lower-level urban municipalities, or any boundary geometry.

The source feature IDs are geoBoundaries/OSM-Wambacher identifiers, not SORS registration codes. The row-level correspondence is therefore a strong name/type/parent candidate crosswalk, not a direct source-ID-to-official-polygon identity proof. The source layer's retained metadata calls its boundary year 2017 but records `sourceDataUpdateDate` as 19 January 2023 and `buildDate` as 12 December 2023; those three fields do not prove the geometry's effective/legal date. The 145-feature source count happens to equal SORS's 145 primary roster codes outside its five Kosovo-and-Metohija statistical-district groups, but this aggregate coincidence does not show a one-to-one mapping or prove national source completeness. The exact other 67 non-scoped features were not expanded into this work item's research set. The source files contain no official polygons. SORS describes its spatial-units register as alphanumeric and geospatial and says its data are obtained from the Republic Geodetic Authority (RGA); RGA describes its Administrative Units Register as including each unit's type, name, registration code, hierarchical parent and polygon ([SORS register](https://www.stat.gov.rs/en-us/oblasti/registar-prostornih-jedinica-i-gis/); [RGA register](https://www.rgz.gov.rs/administrative-units-register)). The SORS web page is a register description, not a dated extract. No dated RGA/SORS polygon extract or official feature-level join key for the 2017 geometries was acquired.

## Individual subjects and parents

`sources/derived/subject-crosswalk.csv` retains all 78 IDs, source feature labels, exact original feature ID/name matches in the retained 145-feature layer, the original geoBoundaries source SHA-256 and metadata dates, the 2017 and current official names/codes, current explicit types, official parent codes/names, match counts, and the explicit geometry limitation. The 2017 workbook marks its state as 31.12.2017 and exposes both administrative-district and city/municipality registration codes. For Atlas labels ending in “City”, the crosswalk matches the workbook's city code/name fields; for “Municipality”, it matches the combined local-unit code/name field. Serbian Cyrillic and Atlas ASCII Latin labels are compared with Unicode normalization, case folding, diacritic removal and Serbian Cyrillic-to-Latin transliteration; `Belgrade` is explicitly crosswalked to official `Beograd`. No source feature identifier is used as an official registry code.

`parent-completeness.csv` gives the Atlas parent ID, current SORS district/city code and name, full current primary roster count, number of distinct scoped codes, and the exact set-equality result. Every selected administrative district has a matching official code and count; the Belgrade parent is a city, not an administrative district. It currently contains one scoped Atlas feature, the `Grad Beograd` city code 79014.

The current-state register separately lists city municipalities beneath cities. The 19 rows in `scoped-city-urban-municipalities.csv` record the 17 current city-municipality records under Belgrade and two under Užice, with codes and names. Those units are not additional subjects in issue #998 and have not been joined to Atlas geometries. This difference in granularity must be kept explicit; a city-level match does not validate or substitute for each city-municipality boundary. SORS's current NSTJ table reports 197 city/municipality and city-municipality entries in its published structure, 174 local self-government units, 29 cities, and 5 cities with city municipalities; its regional table lists 29 local entities in Kosovo and Metohija ([SORS administrative division table](https://www.stat.gov.rs/en-us/oblasti/registar-prostornih-jedinica-i-gis/administrativno-teritorijalna-podela-i-nstj-nivoi-1-2-3/)).

The current roster has 174 distinct primary city/municipality codes. Its five statistical administrative-district groups for Kosovo and Metohija contain 29 primary codes (10, 5, 4, 6 and 4); these 29 are outside this issue's 13-parent scope. The remaining 145 primary codes are distributed across other Serbia districts; they are not all represented by this issue's 78 exact IDs. SORS statistical publications state that certain AP Kosovo and Metohija data have not been available to SORS since 1999 and are excluded from Republic-wide statistical coverage; this is a limit on statistical data availability and does not resolve territorial status, present-day governance, boundary ownership, or the legal meaning of the register's statistical groupings ([SORS 2019 methodological explanation](https://publikacije.stat.gov.rs/G2019/pdfE/G201913046.pdf); [retained SORS 2017 map, marked as of 1 January 2018](https://www.stat.gov.rs/media/2720/oblasti-regioni_2017.pdf)).

The original SORS 2017 administrative-area map explicitly says its graphic base came from RGA, but it is a cartographic map rather than a retrievable polygon dataset. The SORS 2017 code workbook and the current workbook establish official name/code/type relationships and their parent codes; neither supplies historical or current boundaries for validating the retained source shapes.

## Reproduction

Run `python3 data/regional-review/followup-serbia-422-admin-crosswalk-20261005/reproduce.py` from the repository root. The script reads the retained SORS workbooks, captured issue scope, and pinned #422 subject assessment; it writes deterministic normalized rosters and crosswalk outputs under `sources/derived/`, and fails if any subject is unmatched/ambiguous or any current primary roster code is missing from a scoped parent. Runtime versions are recorded in `reproduction-summary.json`. The check establishes register-roster equality for this bounded scope, not polygon geometry correctness. `source/baseline-inputs.json` records the immutable baseline commit and hashes of the issue-pinned inputs plus the #422 subject assessment used by the crosswalk.
