# Southwest China interior batch 2 research packet

As of 2026-10-05, this is an evidence and recommendation packet for the exact 220 IDs in `scope.json` from issue #450. It does not approve the Southwest China regional interior, certify a boundary, or authorize imports. Scope partitioning is a work assignment; Sichuan and Yunnan are partial area subsets, and final combined parent decisions belong to region integration.

## Reproduce

From the repository root using Node 24:

```sh
node data/regional-review/regional-review-524d77d4d47b77c6/verify_packet.mjs
```

The checker reads the pinned world-index parts at baseline commit `062e0585025359c596a887e5a10d3e25479aff21`, verifies the issue's 220 unique IDs and scope hash, checks they are members of the 488-location current Southwest China handoff while preserving the issue envelope/member pins and the 45/90/85 scoped area counts, joins all 203 direct geoBoundaries IDs to one unique feature in the previously retained 2017 source and verifies that source's full hash/count, validates retained ArcGIS item/configuration metadata and the hash of the compact five-feature property observations, checks that the removed live/official responses have restoration-only records with exact hashes and instructions, and writes `assessment.json` plus `reproduction-results.json`. It does not recompute the live ArcGIS response hash or the Sichuan/Xizang official counts because those source responses are not retained. It calls `verify_original_geometry_hashes.py` to recompute the same Python sorted-JSON hash method used by `scripts/reconcile-topology.py`. It does not certify geometry correctness.

### Claim assessment and limits

- **Source, vintage, license, and source role.** The exact prior packet source is a 2,391-feature geoBoundaries CHN ADM2 GeoJSON from immutable upstream commit `9469f09592ced973a3448cf66b6100b741b64c0d`; its exact SHA-256 is recorded in `sources/source-register.json`. Atlas metadata claims 2017, ADM2, County Level, and PDDL 1.0. That license claim applies to the retained geoBoundaries collection and cannot resolve terms for all upstream administrative sources. Atlas metadata for the 17 other IDs names a RESOLVE/Esri ArcGIS Feature Service, reference year 2017, CC BY 4.0, but the item was live when retrieved in 2026. ArcGIS item metadata/configuration and compact five-feature property observations are retained. The full 43,230,525-byte live geometry response is restoration-only because it exceeds the 32 MiB input limit; its retrieval URL, query, exact SHA-256 and attribution are recorded. Official Sichuan and Xizang HTML captures were removed because reuse terms were not established; their URLs, response hashes, byte lengths, retrieval date and restoration instructions remain. The extracted totals are not recomputed by the reproduction script.
- **Territorial meaning and tier suitability.** geoBoundaries ADM2 is a suitable candidate dataset for county-equivalent research, not proof that these particular 203 labels or parents are current. The five RESOLVE ecoregion names are explicitly biophysical. Intersections with rural ADM2 units do not become administrative units solely because Atlas assigned them an ADM2 role.
- **Special structural/semantic screens.** The exact 203 names include 22 romanized names ending in `shi`; their pinyin string is a tier-review flag only, not an official identity/level crosswalk. No source names are blank or match the simple anonymous-remainder screen (`other`, `remaining`, `remainder`, `unknown`, `unincorporated`); this is a name-string check and cannot prove that no remainder territory is hidden in a polygon. Twenty-one of 220 Atlas features are MultiPolygon and five have interior rings; the corresponding 2017 source has zero MultiPolygon and one feature with an interior ring. Every ring passed a simple coordinate-list closure check. These counts do not identify islands, intentional disconnected territories, topology validity, overlaps, holes representing lakes or omitted territory, or adequate neighbor coverage. Five Ngari source ADM2 names are subdivided into 17 repeated ecoregion-named fragments. Those are the observed repeated-tier/fragmentation concern; fragments must be assessed as ecological entities, not assumed counties.
- **Province-sized units and adjacent granularity.** All 28 parent groups and their exact workload counts appear in `assessment.json`; these are identity/count observations from the pinned inventory, not an authoritative current roster. No area ratio, official division map, province outline overlay, border crossing, or neighbor edge was certified. Absence of a detected extreme from structural counts cannot close the province-sized-unit or inconsistent-neighbor checks.
- **Remainders and islands.** There are no blank/generic remainder strings among the 203 source names using the documented regex; the packet cannot establish whether any named polygon includes an administrative remainder. Sichuan, Xizang, and Yunnan are inland, but this task does not substitute that observation for checks of disconnected components, enclosed territories, cross-province boundaries, lakes, or completeness of the region's other coastal/island areas.
- **Completeness and neighbors.** The 203 matches prove only that the scoped IDs occur once in the retained geoBoundaries source file. They do not establish that the source contains all current county-equivalent units, that any source feature covers the entirety of its named unit, or that neighboring China units use consistent tiers. Five names and selected attributes from the live ArcGIS response are retained as compact observations, without any source geometry; the original full response is restoration-only and cannot establish completeness of the 17 fragments.
- **Official current-count checks (restoration-only observations).** At retrieval, Sichuan's 2026-04-01 provincial legislature decision stated 183 county/city/district units, while the issue's full Sichuan area inventory has 158. The captured official response is not retained because reuse terms were not established; the packet records its URL, byte length and SHA-256 for restoration, and the count cannot be independently reproduced from retained bytes. The official Xizang 2026-06-30 code-table capture yielded 74 county-level codes; the exact workload represents 78 distinct 2017 source ADM2 IDs (73 direct IDs plus five parent units split into the 17 physical fragments). Its HTML response is likewise restoration-only, and the count is not recomputed by the packet checker. These differences do not identify units that are missing, duplicated, or wrongly tiered. Yunnan Civil Affairs posted a 2026-08-03 county/township code table, but its full response timed out during retrieval. The partial indexed excerpt is not used for a count or crosswalk. See exact hashes, source dates, limits, and restoration URLs in `sources/source-register.json`.
- **Boundary evidence.** Exact comparison of parsed GeoJSON `geometry` objects finds 203/203 direct Atlas geometries differ from their corresponding retained 2017 source geometry. This is a reproducible difference check, not a geometric similarity, topology, or legality check. Each feature metadata asserts `topology_reconciled=true` and carries an `original_geometry_sha256`; per-row hashes are retained in `assessment.json`. Recomputing the repository's `scripts/reconcile-topology.py` Python sorted-JSON hash method yields 0/203 matches between those recorded original hashes and the exact retained 2017 source geometry. This means source lineage/serialization does not reproduce the recorded original geometry; the expected transformation input and version need engineering documentation and a reproducible reconciliation handoff. This must not be “fixed” by reverting the exact original geometry or by accepting a hash discrepancy as harmless.
- **Outer pins.** The issue's exact ID and envelope pins are preserved. The baseline current macro certificate is version 6 and its SHA differs from issue #450's pinned macro-certificate SHA for its v5 workload. The certificate is not silently repinned; the issue's historical v5 certificate bytes were not found in this packet. The current regional handoff inventory still reproduces the frozen region envelope/member set. See `sources/source-register.json`.
- **Unreviewed checks.** No official current roster/code matching for each of the 203 direct IDs; official standard-division map overlay; boundary overlay against official county geometry; gap/overlap, island, enclave/exclave, disconnected-part or coastline audit; neighbor edge granularity; or correction of the Atlas hierarchy/metadata was completed. The exact limits are listed in each row of `assessment.json` and `reproduction-results.json`.
