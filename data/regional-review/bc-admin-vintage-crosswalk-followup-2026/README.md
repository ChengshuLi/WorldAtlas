# British Columbia 2016–2021 census subdivision crosswalk (#607)

## Scope and disposition

This packet assesses all **376/376** unique 2016 geoBoundaries Canada ADM3 members assigned to the 19 British Columbia grouped units in the merged #485 assessment. Every member has its complete inherited parent chain retained in `source-member-roster.json`, a unique Statistics Canada 2016 CSDUID, and an official 2021 target identity. All 376 source and target CSD parent-division codes agree with the inherited current parent. This is a source-vintage identity crosswalk; it does not change #485 membership, political ownership, hierarchy, shared boundaries, or regional approval.

The original #485 screens are reproduced: 20 no-exact-name cases, five multiple-same-name candidate cases, and 33 below-95% 2021 overlap cases (three below 50%). `exception-review.csv` and `exception-findings.json` account for their union and all additional 2016 extent discrepancies. All 20 name exceptions are individually classified: 10 official same-ID name changes in the transition table; two complete annexations; six asterisk-shortened source labels; one source-text encoding mismatch; and one same-ID change from Central Okanagan J to Central Okanagan West absent from the transition table. The last case is explicit evidence that the table may not enumerate all name changes.

The five repeated names resolve to separate 2016 CSDUIDs using the official 2016 CSD geometry. Across vintages, 374 IDs remain identical. The two documented complete-annexation successors are Skwahla 2 (`5909849`) → Chilliwack (`5909020`) and Langley 5 (`5915835`) → Maple Ridge (`5915075`); each successor is also an original 2016 source unit, so 376 old units resolve to 374 unique current IDs. Relevant event CSV lines, effective dates, file numbers, names and event descriptions are retained per subject.

All 33 inherited low-overlap values were independently reproduced against the retained official 2021 source within 0.002 percentage points. For 16 of those, the official 2016 and 2021 CSD footprints differ by over 5% in at least one direction; 14 have relevant transition-table rows and two (Richmond and Mission 1) do not. The table describes change codes/populations, not polygon area, and warns it may omit changes, so event-to-area causation remains unresolved.

The 2016 source-to-official-CSD comparison also finds 17/376 cases with less than 95% source coverage, 134/376 cases where the selected official CSD area is less than 95% covered by the geoBoundaries member, and 141/376 in either direction. These are exact per-ID measurements in `exception-findings.json`, not corrections. The official product says its full geographic extent can include coastal water; that does not establish the cause of any particular difference. No physical land mask or settlement-completeness test was performed. Lakahahmen 11 (`43193130B91845847390303`) is an additional source-direction case outside the original 2021 low-overlap flags (94.890803% source covered; 89.215424% target covered; its 2021 overlap is 96.188851%). Do not infer land, water, ownership, or boundary error from these ratios alone.

**Unresolved follow-up:** the 141 bidirectional 2016 extent cases need a separately scoped physical shoreline/land and settlement evidence review before any extent correction is proposed. Preserve all source identities and coordinate with the shared BC/neighbor owners if that follow-up finds an inter-region mismatch. This packet does not alter shared geometry or parent footprints.

## Sources and lawful retention

`source-receipts.json` records canonical source URLs, source vintages/dates, access and license notes, retained byte counts and SHA-256 hashes (both compressed file bytes and original uncompressed bytes where applicable), derivation/restoration instructions, and inherited ancestor pins. The files under `sources/` retain the official 2016 Statistics Canada boundary ZIP (23,822,515 bytes; SHA-256 `1bc5638e964d07c289fcdb34553dc593dd16600ec01db16d202c1df28682dd1b`), its BC-only 737-feature transformed extract, and deterministic gzip copies of the exact official transition-table CSV and Census Dictionary page. The CSV and HTML are gzip-compressed without line-ending or whitespace edits because the upstream bytes contain trailing whitespace. The nationwide shapefile is streamed from the ZIP; it is not expanded into the repository. The 2021 Statistics Canada CSD source, 2016 geoBoundaries source, and #485 assessment remain unchanged in their ancestor packet and are pinned by path/hash rather than duplicated. Bounded derived subsets here retain the 376 assigned source features, 374 current 2021 target properties, and 33 low-overlap target geometries.

The 2016 Statistics Canada boundary package is from Open Canada dataset `dee563be-383f-4c6a-91c6-d08ca6638c7c`, “Census Subdivisions, Digital Boundary File – 2016 Census,” under the Open Government Licence – Canada. The 2016–2021 changes table is publication `92F0009X2021001`, canonical table page listed in the receipts; the CSV is retained as received. Its covered interval is 2016-01-02 through 2021-01-01. The 2016 dictionary defines CSDs as municipalities or areas treated as municipal equivalents for statistical purposes; CSD type is an official statistical classification, not a conclusion about sovereignty or political ownership.

The inherited geoBoundaries Canada ADM3 source is release `9469f09`, boundary vintage 2016. Its API metadata reports ODbL 1.0 while `licenseDetail` cites Statistics Canada Open License. This discrepancy is preserved. For 2021, reuse the exact Statistics Canada BC CSD response retained in #485 (2021 vintage, compressed SHA-256 `a16ca45708ab0ccd898994e5e792187d5a108741c2ff6f5f9f74e91242206ad4`; decompressed bytes and source item are detailed in receipts). Reacquire only from the canonical source pages/identified item, then compare metadata and bytes; a current remote response is not asserted to be byte-identical.

## Methods and reproduction

`prepare_source_extracts.py` validates the pinned #485 member IDs, streams the official 2016 shapefile members, selects PRUID 59, transforms from the source CRS to EPSG:4326, and writes deterministic bounded source subsets. `analyze_crosswalk.py` matches IDs/names and geometries to 2016 and 2021 CSDs, reads the official transition rows in the stated interval, and compares areas in EPSG:3347 to reproduce the #485 screening. Invalid projected geometries are temporarily repaired with Shapely `make_valid`; source coordinates and retained source files are never rewritten. `build_exception_findings.py` emits full-cohort dispositions and all 141 extent cases. Dependencies are pinned in `python-requirements.txt` (pyshp 2.3.1, Shapely 2.1.2, pyproj 3.7.2). GeoBoundaries/Statistics Canada overlap and name matches are evidence of statistical-source identity, not cadastral/legal adjudication.

Run from the repository root with these requirements installed:

```sh
python data/regional-review/bc-admin-vintage-crosswalk-followup-2026/prepare_source_extracts.py
python data/regional-review/bc-admin-vintage-crosswalk-followup-2026/analyze_crosswalk.py
python data/regional-review/bc-admin-vintage-crosswalk-followup-2026/build_exception_findings.py
python data/regional-review/bc-admin-vintage-crosswalk-followup-2026/verify_packet.py
```

`evidence-manifest.json` inventories exact candidate file bytes and hashes and pins the ancestor source-member roster, assessment, and source manifests. `verify_packet.py` checks complete ID coverage, target and parent consistency, successor/transition evidence, all exception counts, hash receipts, and deliberate positive/negative controls. `reproduction-results.json` records two-run hashes for generated assessment and summary files. No regional approval, location-attribute import, or historical import is enabled by this evidence packet.
