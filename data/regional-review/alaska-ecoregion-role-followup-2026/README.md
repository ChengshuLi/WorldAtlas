# Alaska RESOLVE fragment source-role review (#601)

This is a source-role correction recommendation for exactly 33 physical location IDs assigned by issue #601. It preserves the stable IDs, current geometries and complete parent chains. It changes no shared data or original #486 source packet, and it does not approve Western North America geography or enable imports.

## Finding

Every assigned location is a distinct RESOLVE 2017 ecological ecoregion portion associated with one 2018 USA ADM2 county predecessor. The #486 packet's audit lists 33 exact intersections, 7 predecessor counties and 15 distinct RESOLVE `ECO_ID` features. Its inherited location metadata for all 33 says `source_role=Counties` and uses a county-tier selection rationale. The `source_id`, exact `ECO_ID`, `original_id`, and sole `source_member_ids` value preserve the separate RESOLVE feature and county predecessor. `administrative_level=Named physical region portion` already describes the current subject; `parent_source_level=ADM1` describes its Alaska parent. The current county role conflates those facts.

The correction recommendation is to remove the unsupported administrative `Counties` role and county-tier selection rationale. Record the RESOLVE ecoregion portion as non-administrative physical geography, and describe its lineage as the named 2017 RESOLVE ecological feature intersected with its named 2018 geoBoundaries/Census county predecessor. Use an agreed non-administrative role value only if engineering confirms the vocabulary; if the field admits administrative roles only, leave it unset pending integration. Keep the county predecessor identity, Alaska ADM1 parent, `reference_owner`, current geometry and each existing parent chain distinct and unchanged. Record the 2017 RESOLVE vintage separately from the 2018 county predecessor; the inherited `reference_year=2018` must not imply a 2018 RESOLVE classification.

`assessment.json` is the exhaustive crosswalk: one row for each of the 33 IDs, with Eco_ID/name, biome/realm/license fields, exact county predecessor ID/name/tier, current role metadata, proposed handling and full location → province → area → region → subcontinent → continent chain. It also records each original geometry part containing the subject, scans all 36 indexed parts for missing/duplicate assigned IDs, and accounts for all 7 predecessor counties and all 15 ecoregions.

## Sources, dates and limits

* **RESOLVE Ecoregions and Biomes, 2017.** Canonical ArcGIS item: <https://www.arcgis.com/home/item.html?id=37ea320eebb647c6838c23f72abae5ef>; official layer and query endpoints are recorded in `scope.json`. The ArcGIS item identifies RESOLVE and Esri and declares CC BY 4.0. Its feature-layer metadata identifies `ECO_ID`, `ECO_NAME`, `BIOME_NAME`, `REALM` and `LICENSE`; data last edit is 2022-01-27, distinct from item metadata modified 2026-05-28. I queried all 15 relevant Eco_ID attributes on 2026-10-04 and retained the exact response and metadata under `sources/`. All 15 rows and their five selected attributes match the originally retained 15-feature source archive. The original compressed archive is 9,761,832 bytes, SHA-256 `b42d888c27a8adae8ee6ec19db430b3d631e34a123847942cc7a07e2528be3d9`; its full-feature bytes remain in the original #486 packet. The RESOLVE project describes natural ecological boundaries, not political/administrative units. Ecology does not establish ownership, administrative membership, settlement completeness or a legal boundary.
* **geoBoundaries USA ADM2, 2018.** The exact source extract and metadata remain in the original #486 packet and are hash-pinned there and in `evidence-quality.json`. Its 2018 metadata identifies the source as U.S. Census Bureau MAF/TIGER, type ADM2, canonical role Counties, and reports Public Domain; it records data update 2023-01-19 and build 2023-12-12. All seven predecessor shape IDs and names match retained USA ADM2 records. Official 2018 Census TIGER/Line DBF attribute rows were independently selected by `STATEFP=02` and exact `NAME` match against those seven pinned geoBoundaries `shapeName` values, requiring one unique Census record per name. The retained fields `GEOID`, `NAME`, `NAMELSAD`, `LSAD`, `CLASSFP` and `FUNCSTAT` identify 3 Boroughs (LSAD 04) and 4 Census Areas (LSAD 05). A geoBoundaries `shapeID` is its own source identifier, not a Census `GEOID`; no Census geometry was loaded or compared. The canonical geoBoundaries reference is <https://www.geoboundaries.org/api/current/gbOpen/USA/ADM2/>; that current API may serve a later vintage, so exact 2018 restoration is pinned to commit `276d72e1f316ad58d52c8fea7974a873c2ec9387`. The official 2018 national County ZIP was fetched from <https://www2.census.gov/geo/tiger/TIGER2018/COUNTY/tl_2018_us_county.zip> on 2026-10-04. It was 79,219,478 bytes (SHA-256 `85e7430567ec47c399e112a0f2fcc19779fbce79dce86cba6ea159256b77d01b`; HTTP Last-Modified 2018-09-18); its 7-row attribute excerpt is retained in `sources/census-tiger-2018-seven-alaska-counties.json`, while the national ZIP is omitted with exact restoration details. The official Census cartographic-boundary documentation is <https://www.census.gov/geographies/mapping-files/time-series/geo/carto-boundary-file.html>. The 2018 ADM2 layer is used here as historical source lineage, not a statement of present legal status or a land survey.
* **Preserved #486 evidence.** Source scope, original assessment, derived-portion audit, original source registry and complete parent-chain archive are read from the exact packet snapshot commit above. Their original bytes and the selected source archives remain unchanged. The original audit's predecessor-union geometry conclusions are inherited only; no geometry overlay was repeated here.

This packet does not decide whether ecological fragments belong in the published location collection at this granularity. That is an integration/model question. It makes no parent or boundary changes and asserts no cross-region inconsistency. The parent packet's separate Alaska–Canada boundary screen remains under its existing coordinated follow-up.

## Reproduction

From repository root:

```sh
python3 data/regional-review/alaska-ecoregion-role-followup-2026/build_assessment.py --check
python3 data/regional-review/alaska-ecoregion-role-followup-2026/test_role_evidence.py
python3 data/regional-review/alaska-ecoregion-role-followup-2026/verify_assessment.py
node scripts/evidence-quality.mjs data/regional-review/alaska-ecoregion-role-followup-2026/evidence-quality.json
```

`build_assessment.py` reads the exact evaluation baseline and preserved source packet from Git objects, verifies the live ArcGIS response against its retained hash, checks the complete 33-ID cohort and generates a deterministic source/parent crosswalk. It is read-only by default. A one-time output creation must use the exclusive `--create` flag, which refuses to overwrite a saved assessment.
