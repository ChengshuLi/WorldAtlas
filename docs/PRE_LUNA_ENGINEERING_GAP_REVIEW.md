## Hosted temporal geography implementation design

The reference release remains a stable, explicitly undated identity/membership framework. A historical administrative association is not necessarily an atlas region, and a political boundary never implicitly reparents a location. Historical names remain ordinary `names`; ownership remains a scalar attribute.

### Collections and enforced storage

Add a forward D1 migration and matching reviewed PostgreSQL migration, without editing already deployed migrations:

1. `geographic_membership_records`: immutable `id`, `entity_id`, adjacent-tier `parent_id` (nullable only for explicitly unresolved membership), `valid_from`, `valid_to`, `source_id`, `method`, `status`, `is_example`, `geographic_release_id`, and original JSON-text `metadata`. Every factual known parent must exist at the selected year. Null membership is explicit unknown evidence, not permission to invent a parent. The renderer can expose a separately labeled reference chain when the historical chain is unknown.
2. `geographic_existence_records`: immutable `id`, `entity_id`, scalar `exists | not_exists | unknown`, supported interval/source/example/reference-release fields and metadata. Entity lifetime bounds remain identity facts; existence claims and withdrawals must not mutate the registry or resurrect an entity outside a sourced lifetime.
3. `geographic_footprint_versions`: immutable manifest identity and source, release, digest, original object key/byte count, location-ID inventory/hash, topology/coverage validation receipt and fixed-grid manifest/hash. Preserve original geographic source geometry separately from reconciled display geometry. One version describes a validated *complete applicable footprint set*, including replacements needed for adjoining territories; partial independent polygons cannot bypass the global overlap/coverage check.
4. `geographic_footprint_records`: immutable supported interval selecting a published footprint version, source, status/method/example flag and metadata. Selection is dated evidence, separate from a reference-release publication. Unsupported years fall back to explicitly labeled reference geography; explicit uncertainty must not masquerade as validated historical geometry.
5. Extend sourced append-only retirements, evidence-history lookup, raw export/restore and import counts to all new dated collections. Replacement plus retirement stays atomic; ordinary imports cannot mutate an existing identity, source, geometry object or claim.

Indexes must support `(entity_id, valid_from, valid_to, id)` for membership/existence, `(release_id, valid_from, valid_to, id)` for footprint selection, and existing `(collection,target_id)` retirement lookups. Retain exact JSON TEXT; do not normalize old source metadata into JSONB.

SQL/import gates enforce no year zero, half-open bounds, source containment, sourced entity lifetime containment, fixed adjacent tier, example isolation, immutable IDs, supported classification/status and nonoverlapping equal-precedence active claims. Validate the *resolved chain at every affected interval transition*, including all descendants of a changed ancestor; testing the changed child alone is insufficient. PostgreSQL concurrent imports need shared advisory locking around a geographic release/affected branch, not only preflight JavaScript reads. Direct evidence outranks derived/reference/example context; unresolved direct evidence blocks weaker historical claims.

### APIs, ingestion and preparation

- Extend `/api/records/import`, the JSON preview, generic compiler/importer and documented examples with membership/existence/footprint-selection claims. Ordinary Luna research imports existing stable IDs; creating or replacing geographic identities remains an explicit reviewed release operation. Every dated import pins the active geographic release and hashes transactionally.
- Add bounded evidence readers for memberships/existence/footprint selections, selected-year `entityProfile` results, retirement history and catalog discovery of immutable footprint manifests. Readers share an ingestion revision and preserve examples/withdrawals exactly like attributes/names.
- Publish footprint manifests only through a maintainer preparation gate that validates licensed source bytes, geometries, global overlap/land coverage, every-location canonical-grid representation and hierarchy consistency. Geography/grids are object-storage products, separate from the website package and ordinary 1 MiB JSON imports.
- A footprint change invalidates spatially derived owner/environment assignments keyed by the old footprint hash. Keep direct evidence on its identity only when its source still supports that territorial meaning. Recompute strict-majority ownership against the applicable land set, or return unknown with the original evidence retained; never reuse old spatial assignments silently.
- Add snapshot capability versioning for dated geography. `/api/map/snapshot` must return resolved membership/existence and withdrawals for eligible geographic IDs plus one complete selected footprint manifest, all at one revision. Include entities necessary to resolve changed parents, and exclusions necessary to remove dated nonexisting locations. An entity pagination filter that drops excluded entities before returning their exclusion would leave stale reference locations visible.

### Shared resolver, client and fixed-grid integration

Adapt hosted rows into `src/temporal.js` history fields `parent`/`existence`; retain the provenance of each resolved link and the separately labeled reference chain. Local server and static/hosted exports must resolve the same records. Do not invent historical tier membership simply because a polity owns a location.

`src/data-client.js` currently merges live attributes/names/withdrawals while boundaries come from fixed exported history. Extend its atomic read/cache to the new geography claims and pinned footprint manifest; cached same-year fallback retains all withdrawals/exclusions. With no trusted snapshot, display only labeled reference geography and unknown dated values. A failed read must not restore a withdrawn parent/footprint claim.

Cache immutable ownership assets by footprint version/hash. Date changes within one footprint version reuse the canonical ownership texture; a true footprint-version switch loads one validated new grid. Membership-only changes refresh province/ancestor membership and reusable boundary metadata without changing geographic cell ownership. `src/main.js` currently calls `rebuildGeometry` when membership or boundaries differ: separate membership-style/border updates from ownership compilation. Zoom, pan, resize and map-mode switches must reuse ownership assets with zero recompiles/uploads. Every parent footprint derives from resolved members; independent parent polygons cannot disagree with membership.

### Executable acceptance cases

1. Dated location → province and province → area changes apply only inside their supported intervals; BC/AD transition and 2027 exclusive endpoint work with no year zero. Local, static and hosted snapshots match.
2. Imports reject skipped tiers, absent parent at any transition, invalid source bounds, cross-release IDs/hashes, example contamination, overlapping contradictory claims and concurrent conflicting branch updates. A complete unaffected chain remains unchanged.
3. Historical administration stored as a generic association never silently changes atlas region/subcontinent membership; political owner changes never reparent geography.
4. Explicit unknown, existence exclusions, withdrawal and atomic replacement all survive pagination/outage/cache reuse. Existing rows/source bytes/predecessors remain readable. Returning to an earlier year restores the correct supported set.
5. A validated boundary change keeps each grid cell in exactly one location, each location in exactly one resolved owner/category, and all parent footprints derived from members. An unvalidated/unpublished/incorrect-digest grid manifest cannot be selected.
6. A footprint switch invalidates stale majority/environment derivations; provenance records old/new hashes and applicable land shares. Source-history bytes are preserved and direct evidence obeys deterministic precedence.
7. Membership-only year changes do not compile/upload geographic ownership. A footprint-version change uploads the matching grid once, followed by zero ownership recompiles/uploads for zoom/pan/resize/mode changes and reuse of that cached version.
8. PostgreSQL/D1 constraints, raw export/restore, ingestion idempotency, examples, retirement history and compact reads cover every new collection. All tracked/deployment assets remain within actual hosting size constraints.
