# Geographic distance audit and downstream impact

This audit records the WGS84 metric changes in PR4, the code that consumes them, and what is known about downstream outputs. It is a code and impact audit, not approval of any proposed boundary or map release.

## Metric rule

Reported geographic distances and geographic nearest-point or nearest-cell choices use the WGS84 ellipsoid in metres. Source lines remain coordinate-linear; they are not silently replaced by geodesic arcs. Some line minima use numerical subdivision and optimization, with the limitations described in `scripts/caucasus-audit/GEODESIC-TOOLS.md` and `scripts/ural-audit/README-WGS84-ROUTES.md`.

Spherical angles, unit-sphere coordinates, and ECEF chords remain only as conservative search bounds. A candidate that could win is evaluated by WGS84 geodesic distance before an output is selected. Projection, polygon, intersection, and grid operations remain coordinate-space/topology operations; pixel-space movement is not a geographic metric.

## Other paths checked

- `scripts/v7-replay/shared_nearest.py` implements the 12-nautical-mile coastal band and nearest-shore assignments using WGS84 Geod distances between water-cell centers and physical coastal land-cell centers. Its spherical indexes and lower bounds only prune candidates; close candidates are checked by WGS84 inverse distance. It is already WGS84 and was not changed by this migration.
- The haversine occurrence in each stage-two `exact_index.py` copy is a conservative lower-bound filter. Selected run candidates are measured by WGS84 `run_pair` before contributing to output.
- Remaining Shapely `.distance()` calls are exact join/coincidence predicates with near-zero coordinate tolerances. Remaining Shapely `.project()` calls locate known intersections or convert a selected on-line point to a substring position; they do not choose a geographic nearest point.
- The browser's `Math.hypot` use measures pointer movement in pixels.

## Verification limits

- WGS84 line, nearest-cell, fixture, and Klukhor projection tests: 19/19 passed after assembly-continuity coverage was added. The raster-backed D8 test could not import because rasterio is unavailable; full real-source fixture tests also need Shapely and rasterio.
- WGS84 hint tests: 4/4 passed; coastal assignment tests: 13/13 passed.
- Retained direct-source-split tests: 14/14 passed; Panama candidate/compose/fresh-validator tests: 12/12 passed. The fresh validator also prints its deliberate synthetic mismatch case as failed, as expected.
- The real-source Caucasus fixture tests were not run because Shapely and rasterio are unavailable in the audit environment.

The current selected-boundary impact remains unresolved. Rebuilding the selector and source-assembly chain requires the exact pinned OSM coastline archive (version `20261105-66c3c6a36802`) and derived Abin/cut inputs from private R2 storage. They were not available locally, and no public source endpoint was verified. Do not substitute a different OSM response or claim map invariance from the historical-guide replay. No map, Neon record, or R2 object was changed by this audit.
