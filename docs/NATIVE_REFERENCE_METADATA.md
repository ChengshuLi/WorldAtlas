# Metadata-only continuation of a selected native reference

A sourced current-parent correction does not require regenerating native ownership
or relabelling its original scientific evidence. The selected native bank and
its original manifest, owner roster, source bank, artifact certificate, latitude
input and current-rebind evidence retain their literal identities (N). A separate
explicit metadata application identifies the current reference (M). An additive
runtime envelope and patch use M as their base and share its hierarchy with their
effective release (E).

This route is general. It does not grant source approval, infer a parent from a
name or location, or replace the existing reference-correction review process.

## Prepare the current reference first

Use `REFERENCE_HIERARCHY_CORRECTIONS`, the ordinary source decision writer,
`prepare-geographic-release.mjs`, and `install-macro-reference.mjs` to prepare and
review the actual complete current source/hierarchy and reference release. The
stock correction receipt must archive the exact original hierarchy and changed
location properties, preserve historical claims, and report zero geometry edits.
The new release must bind every applied receipt through its existing
`metadata.metadata_migration_sha256` inventory. Preserve the original native bank
and its artifact authority; do not replace their hashes with current metadata.

A raw source/hierarchy edit alone is not a coherent current reference. Current
prepared evidence, audits and catalog products must match the new reference
through the existing metadata installer/revalidation path.

## Create the explicit application product

Run the existing delivery preparation entry:

```sh
node scripts/prepare-delivery-handoff.mjs reference-metadata CONFIG DESTINATION
```

The strict version-1 configuration has these keys:

- `selector`: the complete original `data/ownership-selection.json` pin
- `native_manifest`: its original selected manifest pin
- `owner_roster`: its complete original encoded/decoded owner-roster pin
- `current_release`: an exact commit/path locator for
  `data/geographic-releases/current-manifest.json`
- `hierarchy`: complete `before` and `after` hierarchy pins
- `receipts`: the ordered existing source-backed metadata receipt pins
- `source_updates`: exact `{logical_path,before,after}` full containing-source pins

Whole pins include commit, path, ordinary mode, Git blob OID, bytes and SHA-256.
Encoded inputs additionally identify their bounded decoded body. The before
source must be the actual original selected source-bank member. The after source
must be the actual current logical source path. Do not hide a current correction
behind an old encoded source override.

The entry emits `reference-metadata.json` and the ordinary preparation receipt.
It derives M from the real committed release registry, verifies the existing
receipt chain and all complete before/after containing sources and hierarchies,
and records consumed input pins. It does not author a receipt, invent a release
identity, modify a selector, or rerun native science.

## Select and package

Commit the product and add its exact `{path,bytes,sha256}` pointer as
`ownership-selection.json.reference_projection`. Keep the original native
selection and artifact-consumption fields unchanged. Declare the new current
product among ordinary package inputs.

Compose/finalize the additive application with base M and an effective E using
M's hierarchy. Original source evidence, native contracts, assignments, rows,
exceptions and current-rebind products remain literal N. Only application
reference fields and the corresponding effective-domain digest change. The
selected regression gate independently authenticates the complete projection
against the actual selected source bank and current source/hierarchy/release.

The ordinary package consumer publishes the projection at
`reference-metadata/current.json`, adds `referenceMetadata` to the atlas index,
and retains the four original native/additive asset bindings. It consumes current
accepted products rather than replaying historical qualification. Browser loading
authenticates original N ownership/latitudes/physical coverage, derives every
current owner parent from the projection, checks complete changed source
properties, and applies the unchanged strict M/E additive contract. Browser
consumption is not independent source or receipt qualification.

Metadata selections explicitly decline retained-output assembly and use the
existing full-build fallback. An old catalog cannot be reused by repinning its
descriptor. This scoped change does not add a second metadata assembly path. Original compact
native-context callers remain strict; the optional metadata application mode
validates the complete projection before using current parents.

## Verification limits

A successful metadata application proves unchanged leaf identity/index,
geometry, native words and original source meaning plus explicit current
metadata. It is not physical/source approval, whole-parent scientific support,
publication authorization, a delivered-cell count, or a substitute for real
package/browser checks. Existing scientific and publication gates still apply.
