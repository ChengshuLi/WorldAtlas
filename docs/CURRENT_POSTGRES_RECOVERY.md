# Current native PostgreSQL recovery

This is issue #51's current-source recovery protocol. The earlier retained-object receipt proves object bytes, not SQL recovery. Local synthetic fixtures are never a current-production certificate. ENG main owns all production windows and publication on #714.

The manual workflow `.github/workflows/current-postgres-recovery.yml` runs only trusted main, shares the `neon-storage-owner-maintenance` concurrency group, and needs existing Actions `NEON_API_KEY` and `NEON_PROJECT_ID`. It obtains the existing owner connection internally. Passwords travel through hidden stdin to named, read-only native clients. Neither the connection URI nor passwords belong in arguments, logs, Git or comments. This protocol does not rotate credentials, deploy Sites, run provider DDL, rerun baseline imports or change audience.

Before dispatch, ENG main reviews the exact main commit and script SHA256, verifies the current deployed Site/release pins, prepares rollback, establishes and drains read-only maintenance, and agrees with ENG0 on the canonical #51 claim/live flag and operator. A fresh #714 comment authored by the dispatching repository owner/member/collaborator contains exactly one machine window marker:

    <!-- worldatlas-recovery-window:v1
    { ... reviewed window fields ... }
    -->

Required fields: `version:1`, `issue:51`, `queue:714`, `method:"readonly-native-pg-dump-and-isolated-restore"`, `primary_main_commit`, `capture_tool_sha256`, `operator_worker_id:"engineering-central-publication-20261003"`, `operator_github_login` matching the comment author/dispatch actor, `claim_id`, `holder_worker_id`, `claim_branch`, `observed_at_utc`, `expires_at_utc`, `read_only:true`, `drain_verified:true`, `restore_writes_operator` matching ENG main, and a repository GitHub `rollback_receipt_url`. Observation must be no older than ten minutes at start; the complete window is at most thirty minutes and must remain valid at final verification.

`site` contains the exact WorldAtlas project ID, positive deployed version and deployment ID. `source_marker` is the actual complete PostgreSQL V2 read-only marker, including the frozen contract, all 23 collection counts, revision and source/catalog/release/footprint hashes. Never invent this marker or substitute a historic backup. The workflow rejects legacy projections, changed catalogs, unconfirmed live reservations and different production branch/database/owner endpoints.

`backup_recipient_public_key` must be an authorized RSA3072–8192 SPKI PUBLIC KEY PEM, with SHA256 of its DER SPKI in `backup_recipient_sha256`. The private key must stay outside Git with mode0600; never paste it in chat or the queue. A private-key PEM in the public-key field is rejected. Select the recipient with ENG main before the live window; do not rotate existing credentials for this process.

Dispatch the reviewed main workflow with only `window_comment_id`. All source sessions use read-only PostgreSQL options. A session-level advisory lock on `(807245315,1)` coordinates cooperating writers; full original row hashes are compared before and after capture. Restore writes occur only inside a network-none ephemeral PostgreSQL18 container. Table permissions/owners, owner-only migration registry rows, sequence state, raw text and the frozen factual catalog are compared. Restore cleanup and lock release must be confirmed; unconfirmed cleanup is a failure requiring operator settlement before claim release.

The PUBLIC repository artifact uploads only `public-receipts/`: sanitized receipts and an AES256-GCM encrypted native custom archive. Original rows, plaintext dump and private inventories remain in the ignored runner directory and are not public artifacts. AES keys are wrapped to the pinned recipient with RSA-OAEP-SHA256; authenticated context binds exact main, run/attempt, window and source fingerprint. Download and retain the encrypted artifact through the authorized offsite retention mechanism before the 90-day Actions expiry. Runner-local files and expiring Actions artifacts are not permanent/offsite/provider backup guarantees.

Recipient recovery uses `node scripts/recovery-backup-envelope.mjs decrypt ENVELOPE CIPHERTEXT PRIVATE_KEY EXPECTED_CONTEXT NEW_OUTPUT`. Private key and new output must be outside any Git checkout. The output is exclusive mode0600; hashes, context, recipient and AEAD authentication must pass. Record a sanitized recipient acknowledgment with artifact byte/hash pins, without the private key or plaintext content. In-memory encryption verification does not prove recipient recovery. Verify the retained backup through this recipient step before claiming recoverable delivery.

A successful current-source restore receipt proves the stated public-schema/row/table-ACL scope. It does not prove provider physical recovery, server globals, password or role-membership recovery, long-term retention, historical geography approval or physical mobile acceptance. Existing credential/binding setup remains governed by publisher handoff. ENG main separately settles maintenance, restores writes if appropriate, verifies final release pins, and records the window outcome on #714/#51. Only then settle the live flag/release the claim when actual issue acceptance is met; otherwise preserve remaining scope as bounded follow-up proposals within the issue's two-PR budget.

Local checks: `node --test test/current-postgres-recovery.test.mjs test/recovery-backup-envelope.test.mjs`. The explicitly synthetic native fixture is `node scripts/test-current-postgres-recovery-native.mjs`; it uses only disposable network-none containers and no provider credentials. Its receipt must be labeled fixture-only.

Native archive compatibility has two explicit target-only adjustments. `pg_restore --file=-` renders the exact retained archive; only the generated session header before the first archive object changes its empty search path to `public,pg_catalog`, preserving every factual COPY byte. Four CHECK expression trees flatten when PostgreSQL renders and reparses their definitions. After native loading, the target revalidates those four constraints from byte/hash-checked original `postgres/schema.sql`, then must match the unchanged frozen whole catalog. No production schema or catalog pin is rewritten. An archive/hash, unexpected header or original-source mismatch fails closed.

Named source containers are created to completion before starting the secret-bearing read-only client. The lock is checked immediately before/after dumping and its database-level absence checked after release. Native fixture controls cover real session-lock termination, timed-out pre-created clients and independently confirmed container absence. A partial timed-out container creation remains a failure requiring cleanup confirmation; never infer operation settlement solely from a killed CLI.
