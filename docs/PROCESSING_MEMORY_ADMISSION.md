# Processing memory

Selected-geography readers, checkpoint/native comparison, native preparation,
source/physical producers, rebind and package execution use ordinary runtime and
operating-system memory behavior. They do not estimate available memory, reserve
headroom, enforce custom RSS/heap ceilings, or account for parsed/canonical copies,
per-phase carry or retained-object lifetimes. No memory configuration is required.
Large executions can swap, become unresponsive or terminate from memory exhaustion.

Immutable Git identities, complete input rosters, exact byte/hash and decoded-size
checks, valid native dimensions/indices, scientific predicates and complete-output
publication remain required. A failed, interrupted or incomplete execution cannot
supply accepted results; preserve its existing output and rerun into a fresh owned
destination or use the supported exact completed-output resume path.

Historical receipts keep their original resource observations as historical data.
They grant no new scientific authority and impose no current memory policy.
Hosting platform payload contracts, ordinary disk safeguards, independent review,
scientific approval and publication authorization are separate and unchanged.
