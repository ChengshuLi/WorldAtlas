# Shared-land mismatch diagnostics

This compares a frozen candidate land-only baseline with pinned V7 and groups **every differing shared-land cell** into exact eight-neighbor connected components. East and west edges touch, including diagonally across rows. Candidate-only land and V7-only land are counted separately, never included in those clusters. The candidate must match its independently pinned physical mask at every cell. The count 674 is an expected reconciliation finding, not hard-coded.

The comparison is diagnostic. It must not be fed to the map builder as a selector or patch. Existing List 1 citations should be reviewed first, then independently supported portable decisions created in Neon. A cluster can map to several decisions, or a decision to several clusters. Equality with V7 is an acceptance check, not source evidence.

## Inputs and run

Create a JSON config conforming to `list1-land-clusters-config-v1`. Each input is `{ "path": "...", "sha256": "..." }`; all are hashed both before and after processing. Supply `grid` with width, height, step, west -180 and north 90; `candidate_rows`, `candidate_runs`, `reference_rows`, `reference_runs`, `physical_rows`, `physical_runs`; and `provenance`, a set of named, pinned records. `candidate_report`, `physical_report`, `reference_audit`, `decision_snapshot` and `reference_manifest` are required; include selected distance policy/code and source/decision revision where not already captured by those reports. The candidate report must bind the exact grid, candidate outputs, physical inputs, physical report and Neon snapshot. The physical report must bind its grid and outputs, and the V7 composition audit and manifest must bind the reference grid and outputs. Candidate and reference category code, name and physical class must match exactly; land/water classes are derived from the pinned snapshot and reference manifest. Callers must also verify policy and source/decision metadata. Grid files are uint32 little-endian row offsets and `(exclusive column end, code)` run pairs. Baseline uses 0 for its unclassified-water placeholder. The physical stream uses 1 for water and 17 for land; its physical encodings are distinct from category IDs. Candidate and V7 category values come from the validated bindings.

Run `python cluster.py CONFIG NEW_OUTPUT_DIRECTORY`. A complete run creates `report.json` and `clusters.sqlite`. A failure may leave an incomplete directory, but never a complete report; do not treat it as a result or overwrite it. The algorithm keeps one row of intervals in memory; union-find and membership are disk-backed. Set `minimum_free_bytes` in the config and ensure sufficient disk space for intermediate indexes, membership and transaction journals. Free space is checked before work and periodically, but a single SQLite write or concurrent activity can cross the floor between checks. There is no automatic memory watchdog or resume. `clusters` contains stable IDs hashed from the comparison identity and canonical ordered span membership. `resolved` contains `(row, start, end, reference, candidate, root)`, with half-open columns; join `resolved.root = clusters.root`. The min/max column bounds are naive at the antimeridian. Use spans for exact geography.

Run `python match_old_list1.py OUTPUT_DIRECTORY OLD_INDEX INDEX_SHA256 NEW_MATCH_DIRECTORY` with the independently preserved old List 1 evidence index. The optional `--minimum-free-bytes` defaults to 2 GiB and is checked before work and between index items. `matches.jsonl` contains one row per cluster and the old item IDs whose historical changed-land extents overlap. These are discovery leads only: extents are incomplete, an overlap does not establish relevance, and no overlap does not establish absence. Retrieve and inspect cited old evidence and original bytes before proposing new sources or decisions. Keep the complete report and immutable source/index hashes alongside any subsequent reconciliation.

For tests: `cd scripts/v2-baseline/list1_reconciliation && python -m unittest -v test_cluster`. Tests include cell-exact accounting, physical-mask exclusions, diagonal and antimeridian connectivity, deterministic identity, wrapped historical extent overlap, and fail-closed validation.

## Reconcile a reviewed override build

`python reconcile.py CLUSTER_DIRECTORY ORIGINAL_CONFIG POST_CONFIG NEW_OUTPUT_DIRECTORY` compares a later land-only build against the immutable initial clusters and V7. The post config schema `list1-land-reconciliation-config-v1` pins `post_rows`, `post_runs`, `post_report`, `post_snapshot`, `list1_render`, `cluster_links`, and sets `minimum_free_bytes`. It requires the currently supported direct-Neon land build report and a separately produced `worldatlas-new-list1-draft-v1` render bound to that exact report and snapshot. It checks rendered affiliation IDs against the build's selected decision trace and the post snapshot's category mapping against V7. Unsupported witness traces fail closed; source and renderer authenticity require independent verification.

The links JSON schema is `list1-cluster-links-v1`, with `comparison_sha256` from the initial report and `links` containing `{cluster_id, entry_ids, decision_ids, rationale}`. Supply only reviewed, explicitly curated links; the tool does not infer causation. It checks linked IDs occur in the rendered entry decisions, but does not prove those decisions geographically explain a particular cell. Unknown, duplicate, or unbound IDs fail. Omitted cluster links remain visibly unattributed.

`clusters.jsonl` records initial cells, now matching V7, still mismatched, and any supplied links. `report.json` separately records unlinked clusters/cells, unexpected extra changes to initially matching shared land, and the original physical-mask disagreements. The post build must preserve the candidate physical mask. `numerical_acceptance` means only zero remaining shared-land mismatches and no extra changed shared-land cells; source support, attribution, conflict handling, and changes outside shared land need their own review. The program is research validation, not an override or publication tool. Run both test modules with `python -m unittest -v test_cluster test_reconcile`.
