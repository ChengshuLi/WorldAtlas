# Reproducible V5-cut-based V2 research hypothesis

These are **unreviewed example inputs**, not an assertion of the historical V2 boundary. They capture the exploratory source-cut and water-side connector choices used for the current baseline candidate. The later V5-derived cuts, chosen route endpoints, literal connectors and closures have not been established as the original V2 rules. Do not treat them as accepted geography.

The three `*-route.example.json` files contain the exact global-cell windows/endpoints and hashes of the earlier candidate physical streams. Replace only the `/path/to/...` fields with the corresponding verified local files; run each with `../build_water_route.py` in a new output directory. The physical streams used in this check were produced under the earlier, narrower Overture selection. A later hash-verified scan showed both Overture selection predicates choose the same records in the 32 pinned shards, but a fresh global raster comparison under the revised code has not been run.

The region example pins the recovered source-cut GeoJSON SHA-256 `b0401ee291aff8b6b5fdaabb4501e7321cbf6c8e9eba9be19cdca6e7ab846382`. Replace its path with the verified file, and replace each route-report path and `REPLACE` digest with the freshly generated report. Then run `../build_regions.py` in a new output directory. The output polygons are caller-selected hypotheses; literal connector coordinates are explicit in the config, not automatically inferred or verified as historical.

A validation run reproduced all three saved water paths byte-for-byte. The resulting Europe and North America polygon coordinate arrays exactly matched the earlier exploratory polygons. Canonical compact sorted-JSON geometry SHA-256 values were `54537fa1f0f7ba278901bb9385045bf6d6ab3f717ba712ec0b32f121fb833679` and `47e3289895426c18a10f63ca4c13718bbe9914202db943f311281a173e3fde9e`, respectively.
