# Standalone simplified V2-style land baseline

Research only; not a recovered exact historical algorithm or a published map. This produces land labels only. A separate stage must assign water, and a separate comparator may read the frozen V2 map. The builder never reads V2/V6/V7 labels, difference spans, a Neon export, named islands, or named-sea exceptions.

## Inputs and output

`/usr/bin/python3 build_land.py config.json NEW_OUTPUT_DIR`

Config schema is `simple-v2-land-v1`. `grid` has `width`, `height`, `step`, `west` (-180) and `north`; a full 360-degree wrap is required. The following fields are `{ "path": "...", "sha256": "..." }` pins: `physical_rows`, `physical_runs`, `mainland_rows`, `mainland_runs`, `physical_report`, `seed_provenance`. The physical report must bind the grid and physical streams. The seed report must bind the mainland streams and the exact component rows/runs regenerated from the physical input. These checks establish integrity, not authenticity or geographic acceptance. Optional `workers` is 1–8 (default 1), `chunk_columns` 1–1024 (default 128), `tolerance_metres` 0–1 (default 0.00001), and `minimum_free_bytes` (default 2 GiB). Use a new output directory outside the input directories. The reserve is checked at stage boundaries and during streaming, but a single external component-builder or index write can still cross it between checks.

Physical input is canonical little-endian row-offset u32 and `(exclusive_end, code)` u32 runs, with water=1 and land=17. Mainland input has the same RLE format and covers all cells of each selected mainland physical component with categories 17–22, with zero elsewhere. Every category must occur. A seed may partition a connected mainland root into several categories but cannot partially select a root. The tool generates physical components itself, validates full seed-root coverage, and never reads a legacy continent map. Output `rows.u32le`, `runs.u32le` uses zero for water and 17–22 for land. `report.json` pins inputs, program code and output, states methodology, includes tie cases, and is required to interpret the result.

The independent source-derived mainland seed is required. Exact V2 continent cut geometry is not established by these files; if the proposed later V5-derived cut lines are used, they must be identified as a deliberate approximation in the seed provenance. Historical records state V2 assigned components by distance to mainland shore, but do not establish all geometry, tie rules, or implementation details. This builder approximates shore distance with minimum spherical *cell-center* distance from all cells of an island component to all mainland seed cells. For distinct land components a nearest point normally lies at the mainland boundary, but this is not the same as the continuous exposed coastline. Four-neighbor connectivity wraps at the dateline; components do not join across a pole. When distances are within the tolerance, the lowest code wins and the tie is reported. These are explicit implementation choices, not verified V2 facts.

The seed index is tiled with bounded caches; all unseeded component runs are queried (not a sampled representative). Runtime on the 7-billion-cell global grid can be substantial and must be measured for the actual inputs. Failures may leave a partial output directory, which is not a result; rerun with a new directory. No source authentication, geographic acceptance, or production deployment is implied.

Run tests: `/usr/bin/python3 -m unittest -v test_build_land` from this directory. The reused nearest-distance and tile-index tests are in `../v7-land/direct-neon-land/test_nearest_mainland.py`.

## Partial 12-nautical-mile water band

`coastal_band.py CONFIG NEW_OUTPUT_DIR` consumes the physical streams and the completed simple V2 land report/streams. It evaluates water-cell centers in one configured tile against the spherical physical-grid shoreline. It assigns the nearest continent water code within 12 nautical miles (22,224 metres), with a 10-micrometre numerical tie tolerance and lower-code tie priority. The spatial halo must certify that omitted shores cannot change any answer; otherwise the stage fails and requires a larger halo. These geometry and tie conventions are explicit approximations, not recovered historical V2 facts. The result is a sparse, partial research layer: **water beyond the band remains unassigned** because the historic ocean partition is not established. A completed tile is not a complete V2 map. No V2 labels or named-sea exceptions are inputs.

The output report pins the physical and land streams, land report, code, and compressed tile spans. Each tile needs a distinct output directory. The default free-space reserve is 2 GiB; it is checked before creating output and during row processing, without guaranteeing against external concurrent writes. Run `python -m unittest -v test_coastal_band` for threshold, tie, input and free-space checks. A global tessellation, ocean assignment and comparison remain outstanding.

## Separate land comparison

`compare_land.py CONFIG NEW_REPORT.json` compares the candidate land streams to pinned preserved V2 streams without using the latter to build the candidate. It reads run intervals, not individual grid cells, and reports a continent confusion matrix, the number of matching and different continent assignments where both are land, and physical land/water discrepancies separately. The reference is validation only. Copy `compare-land-config.example.json`, provide paths and hashes, and choose a new report outside the input directories. Run `python -m unittest -v test_compare_land` for the synthetic comparison test.
