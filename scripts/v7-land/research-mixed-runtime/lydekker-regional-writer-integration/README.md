# Mixed-writer integration preparation
This is an experimental preservation checkpoint. It does not activate the regional rule in the driver. An independent reviewer found no new blocker in the bounded bridge and source-resolver tests; full driver activation has not been reviewed.


This local research helper maps a freshly computed, authenticated regional result to the existing whole-component mixed-writer claim shape. It preserves selected source affiliations, holds explicitly pending roots, refuses stale snapshot/component/line pins and conflicting or reviewed regional proposals, and keeps a separate audit trace for the regional rule. It does not read a saved historical comparison or write a grid.

The existing writer was exercised with a tiny synthetic row, not a world-map build. Before production use, the caller still needs to export and authenticate the selected Neon regional record, rerun the source/group/line and satellite resolvers from pinned physical inputs, supply the current known pending roots and protected witnesses, and bind the complete regional policy and code into the writer request and report. The mixed driver currently requires its reported affiliation-statistics keys to exactly equal the selected List 1 affiliation IDs. Integrating this additional rule therefore also requires separating the regional rule's statistics from that existing equality check. This helper is not connected to the mixed-land driver and no map was built.

Every independent region-claim channel must be wrapped with `protected_region_rows`; otherwise a pending, protected or reviewed root can still be changed through that separate overlay path. The bridge unions pending roots explicitly reported by the regional run with caller-supplied pending roots. Withholding new claims does not make cells unassigned: the current writer retains their baseline codes. The per-root trace carries line, satellite or group evidence separately from the synthetic writer affiliation; production wiring must bind that trace to the same-run policy, source and physical lineage. The helper cannot itself distinguish a freshly computed result from a reloaded preview: same-run authentication remains a caller obligation.

`source_groups.py` is an experimental source resolver for the selected policy's eight OSM features. It checks exact source and physical-input bytes, re-extracts pinned geometries, validates each named witness against its polygon and current component, and emits only complete-component windows plus independently named anchors. The supplied `run_source_groups.py` is a bounded workspace-specific diagnostic, not a production invocation or a substitute for a supervised process and source-catalog authentication. Its small synthetic tests are not an independent geographic review.

The bounded workspace diagnostic re-extracted all eight pinned features from the authenticated source archive, validated their named witnesses and complete-component coverage, and found six independent named anchors. Its fresh root sets matched the prior bounded source diagnostic. No map was built. This validation does not prove all group membership or a complete pending inventory.
