# Caucasus real-source direct-v2 fixture

On 2026-11-05, after the direct-v2 freeze in PR4 commit `b2f4648f84825e8c19cc15d606ca6b278a263e09`, `test_caucasus_v2_real_source_fixture.py` passed on macOS using the pinned direct-v2 producer and the real water-closure checker together with the actual Caucasus raw-source reconstruction. It independently replayed the sources after seed generation and verified the original snapshot pin, the derived boundary and region digests, and the new checker and contract pins in the resulting proof.

**Scope:** The selected line is a real saved guide and the two raw source files and recipe bytes are real. The snapshot and its catalog, 40×40 grid, physical mask, components, witness resolution, region closure and physical encoding evidence are synthetic test data. The Panama direct-v2 producer is real, but this fixture does not select a Panama boundary or use Panama's OSM archive. The water checker is the real v2 checker on synthetic water. Executable allowlists are patched **only in test memory** to permit the test fixture; this does not promote them or review the producer. The gate is called in process and the derived view is independently replayed, but this is not a test of the outer orchestrator, a production closure, the final map, or geographic correctness of the watershed. No real Neon record was changed.

Run from `scripts/caucasus-audit` with the pinned input files and direct-v2 source tree available:

## Binding subprocess with frozen allowlist

`test_caucasus_v2_binding_real_source.py` runs the same pinned real-source assembly through `caucasus_stage2_binding.run_seed`, which invokes the actual gate as a subprocess. With the PR4 frozen direct producer `48d5719ca263ac28f9433c729d413207f069caa23fb72513d647ed26edd42b35`, all three executable pins matched the frozen allowlist and **no allowlist patch** was needed. On macOS the bounded run passed 1/1 in 8.139 seconds. The test independently replays the sources and checks the gate's producer and derived-view pins, original snapshot, real checker/contract proof and synthetic output.

Use the same environment variables and real local inputs documented above, substituting `python -m unittest -v test_caucasus_v2_binding_real_source`. The input snapshot and source catalog, 40×40 grid, region closure, physical mask, components and resolution remain synthetic. This is not the outer orchestrator, production closure or a rebuilt map, and it does not establish that the source-derived line is a correct watershed. No Neon data was changed.

A subsequent run also passed the actual gate and seed reports into `caucasus_stage2_binding.validate_seed`, which independently replayed the raw inputs and checked the gate report. Its validator callback was a **test probe**, not the strict core validator. This run passed 1/1 in 9.695 seconds. The separate `test_caucasus_real_contract_adapter.py` exercises the real strict validator with a synthetic seed report; the two tests do not demonstrate the complete direct outer/core path together.

## Direct producer and strict selected-decision crosswalk

`test_caucasus_v2_core_real_source.py` combines the raw Caucasus reconstruction, real binding/gate subprocess, frozen v2 producer and water checker with the actual PR4 `contracts.validate_selected_seed_decisions` callback. It independently replays the source inputs through `binding.validate_seed`, verifies the seed trace and also rejects a forged producer pin in the gate report. The synthetic grid is global 80×40 at 4.5 degrees, and the fixture uses a synthetic snapshot, catalog, component mask, route and closure. Its route's stored physical/checker/contract provenance matches the freshly generated synthetic closure proof; it does **not** cover the distinct historical-vs-fresh route-provenance case.

On macOS the pinned run passed 1/1 in 13.547 seconds using `contracts.py` SHA-256 `ed2f78031508d8202358c9b9698f1446128855986d1c2ffcdb35a2f30a6d53d9`. Use the source environment variables above, ensure the pinned strict stage-2 contract is importable, and run `python -m unittest -v test_caucasus_v2_core_real_source`.
