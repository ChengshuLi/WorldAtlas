# Sealed coastal tile batches (research only)

`batch_coastal_tiles.py` runs the existing WGS84 coastal tile generator for a list of non-overlapping tiles. It copies the four SHA-pinned physical/final-land RLE files into Linux memfds, verifies each while copying, and seals them against writes, growth and truncation before any tile runs. Each tile uses these same pinned bytes. The policy snapshot, tile plan and report lineage are checked before and after generation from bytes read and hashed through the same file descriptor. This narrow implementation accepts only the legacy `direct-neon-land-build-report-v1` lineage; streaming, nearest and current mixed-land report modes are rejected. Tile code and manifest hashes are bound to a completion record, written only after every tile and the second metadata check succeed.

The plan is a small JSON object with exactly `tiles` (a nonempty list of [x0,x1,y0,y1] arrays), `pad_degrees`, `chunk`. Input snapshot, physical/land grids, both reports and plan must be under `--input-root`; each has a SHA-256 argument. Output must be new and must not contain inputs. Use `--allow-unverified-snapshot --allow-draft --allow-selected-research-policy` only for an explicitly selected research policy. `--help` lists all arguments. A partial directory after failure is not a completed batch; never consume its tiles. A valid `batch-complete.json` is necessary but is not sufficient to establish global coverage, scientific correctness, Neon acceptance or publication readiness. Existing research-only policy and land-lineage gates remain unchanged.

Linux `memfd_create` and sealing are required. These file-backed-memory pages count against process/container memory and coexist with NumPy, SciPy and other work. On this dataset the two run files alone total about 407 MiB; assess actual available memory and concurrency before use. A source that changes while being copied fails the digest/stat checks; later source changes cannot modify the sealed snapshot. On-disk code hashes are change indicators; they do not prove which bytes Python imported before hashing. The driver's checks protect input bytes, not the authenticity of catalog assertions or the correctness of the source. No full global run, realistic worst-case coastal-density benchmark, or current mixed-land lineage compatibility is claimed.

Run focused synthetic tests from the script directory with the project Python environment:

    python -m unittest -q test_batch_coastal_tiles
