# Direct research composition

These tools operate on new physical and land grids rather than a prior continent-labeled map. They are candidates, not an accepted or publishable V7 build. All decision snapshots are unverified; an explicit `--allow-unverified-snapshot` is required. Draft evidence additionally requires `--allow-draft-snapshot`. A shared basin also requires `--research-shore-method spherical-grid-edge-v1` in the basin builder and `--allow-research-shore` in both prefill stages. That shore metric is a research choice, not a reviewed Neon decision.

1. Build physical rows/runs with `../v7-raw-mask/build_physical.py`; pin its candidate report and output hashes. Export a fresh draft using `../v7-decision-export/draft/`. Compile the land stage with `../v7-land/direct-neon-land/`; its report binds the physical and component streams, snapshot and resulting land rows/runs. The optional single-generation streaming path produces a distinct top-level report, whose nested report, physical report and manifest must be pinned and checked; same-run lineage is not independent verification.
2. Extract each selected SeaVoX feature and run `build_seavox_basin.py` with the pinned archive, extraction manifest, decision snapshot and physical streams. Shared basins additionally require the new land streams. Run `verify_basin_coverage.py` with the output manifest and its SHA, the same pinned snapshot and physical streams. It checks all emitted spans against the source raster and physical water; it does not prove polygon semantics, shoreline correctness or source selection.
3. Supply `build_prefill_plan.py` an input configuration with `rle_inputs.physical`, `rle_inputs.land`, `coastal_band`, and exactly the selected `basins`. Each RLE entry has `rows_path`, `runs_path`, `rows_sha256`, and `runs_sha256`; the direct land entry also has `report_path` and `report_sha256`. The physical entry carries `physical_mask_sha256` from the physical TIFF. The plan binds the land report, snapshot, sources and explicit precedence. The land report must bind the canonical grid and physical inputs. Same-run component artifacts are rehashed for integrity; that read is not independent connectivity recomputation. The coast generator and reviewed coast policy remain outstanding. Run `build_prefill.py` with that plan to produce the prefill audit and streams.
4. For a draft ocean run, `../v7-recovery/ocean/make_candidate_build.py` binds the snapshot to the new physical report and output hashes. The ocean runner requires that manifest and digest, and reports unseeded components. Closed waters need a separately reviewed generator.
5. `compose_direct.py` consumes a `worldatlas-direct-final-plan-v1` JSON. It requires grid width/height, decision snapshot hash, decision and entity revision IDs, revision status, a `prefill` object with `rows`, `runs`, `audit`, and `plan` paths and SHA-256 fields, and water layer descriptors. Each layer specifies its ID, pinned manifest, priority, explicit overrides and allowed codes. Layer manifests must bind the same prefill streams and decision snapshot. The composer refuses a layer that overwrites assigned cells or leaves any water unassigned. If the prefill used the research shore method, the composer also requires `--allow-research-shore`. Paths resolve inside `--input-root`; output must be new and outside that tree. The final report is research-only.

A manifest's coverage flag and a local snapshot hash are assertions, not independent geographic validation or approval. Full source coverage, coastal and closed-water generation, reviewed decision completeness, global connectivity and final UI/attribution checks remain outstanding. `compose_full_water_grid.py` is a separate historical replay tool and still reads V2/V6 inputs. The prefill planner and builder default to direct land and require `--allow-historical-v6` to use the historical V6-only replay path.

Draft coast, closed-water and ocean policies require an explicit research-selection marker before execution. An unselected or unmarked policy stops the relevant builder; its presence in an export is not an approval.
