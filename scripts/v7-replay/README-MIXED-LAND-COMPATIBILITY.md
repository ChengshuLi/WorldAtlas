# Mixed-land reuse: strict snapshot comparison prototype

This is a local diagnostic, not a water input adapter and not authorization to run or publish. `compare` reads two supplied byte strings only after checking their SHA-256 pins and 16 MiB cap. It supports draft v1 and v3 Neon-export representations. It strips the two named water policy kinds, normalizes only schema-defined top-level decision-revision fields, excludes revision-level evidence, and otherwise requires all snapshot content and ordering to be exactly equal. Comparisons are type-aware: JSON booleans, integers and decimal-form numbers are distinct, and decimals are parsed without binary64 rounding; harmless representation changes can therefore fail closed. It requires that the land snapshot had no water policies and the other has exactly one of each kind. A match does not validate the new policies or their selected status, and cannot establish equivalence for a consumer that inspects revision-level evidence.

An actual reuse adapter must additionally authenticate the complete land-build config and all source bytes against their selected R2/Neon pins, validate stage-2 and physical lineage, bind the exact mixed build report and output hashes, require its completed monitor and independent root-trace/reconciliation proofs, and confirm compatible policy schema. The current monitor does not cryptographically bind the command it observed; the current water snapshot reader explicitly does not authenticate Neon acceptance. Those limitations cannot be erased by a projection match.

This strict comparison intentionally rejects water-side additions to any other field, including new basin or source records, even if they might be harmless to land. A useful complete water snapshot will likely require a more carefully reviewed, explicitly versioned projection or a fresh combined-snapshot land build. The v3 land export is currently rejected by the active water snapshot reader. No geographic decision, database selection, or water build is performed here.

Synthetic tests: `python -m unittest -q test_snapshot_compatibility`. A separate read-only probe matched the actual draft-103 land snapshot against an in-memory artificial two-policy overlay; this did not authenticate or execute a real combined revision.
