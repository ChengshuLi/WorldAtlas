# Pleiades v4.1 Iberian place-name source evaluation

## Scope and finding

A purposive, non-exhaustive sample of 25 Pleiades place resources was read from the pinned v4.1 release. The selection used its v4.1 name index to locate historically familiar candidate records and the source GIS place index representative coordinates to bound the retrieval to a broad Iberian search rectangle. That rectangle is a retrieval aid only; it is not a peninsula boundary or an Atlas geography. Sample is not statistically representative. The bounded evidence supports evaluation of selected ancient names; it does not support exhaustive alias lists, continuous habitation, preferred-name chronology, or territory-level attributes.

Pleiades name records expose `attested`, `romanized`, `language`, broad `start`/`end`, period attestations and confidence vocabulary, with record-level references where present. A reference and a period label establish what Pleiades records, not independent verification that every name was continuously used throughout the broad interval. Broad bounds are preserved verbatim and are not converted into annual or continuous intervals. `confident` is the source vocabulary, not a numerical probability. Some records have no `citesAsEvidence` link for the selected name; keep them as provisional catalog assertions, not citation verified claims. Modern or mediaeval records are excluded from claims about 500 BCE–500 CE.

No Pleiades location geometry, coordinates, or place-to-Atlas assignment is transferred. Place type is retained only to distinguish settlement resources from territorial units; this campaign does not measure habitation. No approval certificate exists for importing any regional attributes, and no import was attempted.

## Release, license, method

Canonical release: [Pleiades datasets v4.1](https://github.com/isawnyu/pleiades.datasets/tree/v4.1), tag commit `c4423b89541d752792d84fab5d824c7a2db96a44`, published 2025-05-28. Pleiades states dataset license CC BY 3.0; individual contributors retain copyright. Per-resource contributors, exact raw JSON URLs, retrieval status/date, byte lengths and SHA-256 are recorded in `source-manifest.json`. Original selected JSON bytes can be restored from those immutable v4.1 URLs and hashes; they are not duplicated as raw files here. Discovery aids: v4.1 [README](https://raw.githubusercontent.com/isawnyu/pleiades.datasets/v4.1/README.md), [downloads](https://pleiades.stoa.org/downloads), name index `data/indexes/name_index.json`, and GIS places index `data/gis/places.csv`; retrieval sizes and hashes for these entry points were logged in the research checkpoint during collection.

Selection was purposive (25 named candidates), constrained to coordinates in a broad WGS84 retrieval rectangle (approximately 35–44°N, 10°W–5°E), and then checked against the pinned v4.1 resources. Coordinates were used only for source retrieval selection and are not retained as evidence or geographic decisions. The retained output reports one representative ancient name record per Pleiades resource, favoring a source-linked attestation when available. Names, citations, chronology and confidence are source assertions; no independent ancient-text or epigraphic edition review was completed.

The dataset release date is known; the observation/publication date of each ancient name is not equivalent to this release date and often not encoded as a separate field. The source's date endpoint/calendar convention and whether `start`/`end` are strict observation bounds versus editorially assigned spans were not independently verified in this pass. Sparse period labels are not annualized. No named resource is assumed continuously inhabited.

## Coverage gaps and next work

This closes only the declared source review for these 25 resources. The sample does not cover every Iberian ancient place, names without Pleiades resources, variant spellings not represented by selected records, non-ancient names, or independently collated text/epigraphic evidence. Several selected name assertions lack a `citesAsEvidence` link; others link a primary text locator or epigraphic catalogue entry but still need source-level review before any future use. Follow-up should be a bounded verification issue for named source records only, retaining contested readings and independently established date bounds.
