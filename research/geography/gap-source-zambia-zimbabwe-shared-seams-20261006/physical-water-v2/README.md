# Dated physical water and land-cover evidence (WorldCover 2021)

## Source and intended interpretation

This packet retains the official ESA WorldCover 2021 v200 (product version V2.0.0) 10 m land-cover map for the complete #1234 candidate extent. The map is derived from Sentinel-1 and Sentinel-2 observations for 2021; it is independent of the consumed geoBoundaries administrative source. It is a land-cover classification, not a legal boundary or a hydrological inventory.

The [ESA product access page](https://esa-worldcover.org/en/data-access) identifies the 2021 map, class legend, and CC BY 4.0 reuse terms. The retained Product User Manual and Product Validation Report are the primary source records under `sources/`; their HTTP headers, exact sizes and SHA-256 digests are retained with them. The COG’s embedded metadata records the product version, time interval, tile ID, CRS, grid and license.

The relevant class codes are 80 (permanent water bodies) and 90 (herbaceous wetland). Class 80 supports a statement that WorldCover mapped a pixel as permanent water in its 2021 product; it does not alone establish the present channel, shoreline, physical state at another date, or legal placement. Class 90 is retained separately and is not recoded as open water. Other named land-cover classes are reported as mapped non-water land-cover classes; their absence of class 80 does not establish dry land. Unrecognized values remain unclassified.

The v200 Product Validation Report (PVR V2.0, Table A2.1, page 27) reports sample-based Africa-wide user's accuracy of 91.0% ± 2.8 for permanent-water class 80 and producer's accuracy of 91.5% ± 4.6. Its Table 3 (page 16) reports Africa overall accuracy of 76.5% ± 1.3; the global overall accuracy is 76.7% ± 0.5 (Table 2, page 15). These are regional product-level sample estimates, not accuracy estimates for any of the ten candidate geometries, and they say nothing about this tile’s absolute registration or shoreline error. The PVR describes reference-image geolocation shifts and label ambiguity. The product documentation does not declare a candidate-scale absolute registration tolerance. Therefore pixel-edge disagreements remain unresolved at the product’s nominal 10 m scale.

The source grid is EPSG:4326 with 1/12,000-degree cells and origin 27°E, 15°S. Tile `S18E027` spans 27–30°E and 15–18°S. The source classification period is 2021-01-01 through 2021-12-31 UTC. CC BY 4.0 applies; attribution is to ESA WorldCover 2021 / modified Copernicus Sentinel data processed by the ESA WorldCover consortium.

## Classification protocol and status

The completed measurement preserved every candidate component’s full original geometry. It intersected that geometry with the source’s actual 2021 class cells, retaining portions by class code and separately checking complete coverage. Counts are counts of touched map cells, not geodesic area or candidate-specific accuracy. Class 80 is reported as mapped permanent water, class 90 as mapped wetland with open-water status unresolved, the other named land-cover classes as mapped non-water land cover, and unrecognized or unobserved portions as unresolved. No feature will be snapped, buffered, repaired, simplified or reassigned. The source map alone cannot establish processing cause, political ownership, boundary authority, legal dry land or release suitability.

Each run’s output is a `worldcover-classification-index.json`, one ordered JSON shard per complete component result, one ordered shard per retained contact fragment, and an `execution-receipt.json`. The index records shard paths, sizes and SHA-256 digests so the complete result can be reconstructed without dropping records. Every ordinary output file is checked against a 32 MiB cap before any output directory is created; each run is capped at 64 MiB including its receipt, and both runs together at 128 MiB. The synthetic output-writer control checks index/receipt hashes, reconstruction of component and contact records, oversized-file rejection before write, aggregate caps and no-overwrite behavior.

After both actual runs, `verify_classification_runs.py` verifies every receipt, index and shard; all ten component IDs, four contact subjects, every local contact-intersection pair, original contact-fragment IDs and original contact geometry hashes; per-file/run/pair caps; identical frozen inputs and producer; and exact result-shard reproducibility. Its `--inventory-only` mode checks the exact 10/4/21/2 source roster directly from preserved vector inputs before raster execution. Its `--controls-only` mode checks a synthetic reproducible pair and rejects a byte-mutated shard without touching raster data. The verifier derives `source_geometry_compressed_bytes_each` from the full pinned source gzip, checks the complete production pair, and has an adverse control that rejects a one-byte-wrong expected size. Run `--frozen-inputs frozen-inputs-run-one-and-two.json` to audit the original production freeze; `frozen-inputs.json` is the later audit/tooling freeze and is not a classification input. Pair verification passes: 13 listed result files per run have identical hashes, all 10 component and two fragment shard descriptors match, and both receipt-inclusive bundles are 15,615,087 bytes. `--controls-only` and `--inventory-only` also pass without raster reads.
