# Portugal–Spain seam source investigation

This packet covers only the seven exact subjects and complete retained component `gap:ad2052defbeba8e89287bcc4344e641225c6579f9afd584497b381fe8fd8eedc` in issue [#1106](https://github.com/ChengshuLi/WorldAtlas/issues/1106). It compares source membership and dated official records. It makes no territorial ownership, physical land/water, or legal-boundary certification and proposes no map repair. The broader Portugal/Spain interior scopes in #242/#243 are outside this packet.

## Conclusion

No source-supported engineering seam edit is proposed. The baseline importer and exact provider bytes establish which source geometry Atlas used; official records provide dated diagnostic line geometry and administrative features. The retained material does not establish a single mutually authoritative Spain–Portugal international line with a point-by-point coordinate realization and a crosswalk to both countries’ present municipal units. The official IGN `url_resource` fields point to product-record pages, but those records and coordinate annexes were not retrieved or verified in this packet. The IGN rows marked `agreed` therefore remain item-level attributes, not proof of bilateral authority. Their documented official administrative geometry can still support a transparent current-reference comparison, with that limitation explicit.

For Spain, all 55 exact geoBoundaries member IDs attached to the three Atlas districts were found in the complete 8,205-feature 2018 ADM3 raw and simplified files. All eight selected IGN border items uniquely match a named member among those IDs. Each selected row is a dated `LineString` with `legalstatus=agreed`, date `2022-04-04`, method 3, and an official record URL. A separate current IGN `administrativeunit` collection supplies complete municipality polygons for all eight Spanish names. Seven exact `nameunit` queries matched directly; Zarza la Mayor’s exact name query returned zero, but its complete 2022 line feature carries Spanish nationalcode prefix `34111010218`. Querying that exact code returned only municipality gid 1173184, whose complete native item identifies Zarza la Mayor (`ES`, `Municipio`, `MultiPolygon`). This is an exact source crosswalk, not a geographic inference. The collection/item response does not state a polygon validity date. The Spain–Portugal country-level control record is dated `2026-07-02` and has an explicitly nil/unpopulated legal-status field. The agreed `Brozas#Villa del Rey` interior line is retained as a negative control, not a border candidate.

For Portugal, all four exact Atlas geoBoundaries IDs and names match complete direct CAOP2025 municipality API items: Nisa (DTMN 1212), Idanha-a-Nova (0505), Castelo Branco (0502), and Vila Velha de Ródão (0511). Their whole geoBoundaries 2020 originals and baseline simplified files are separately retained. CAOP is an administrative cartographic product, and its municipal polygons do not independently establish an international line. The API collection title says CAOP2025 while its declared temporal extent is 2000–2007; this metadata conflict remains visible in the report.

The areal ledger distinguishes complete polygon coverage from line contacts. The union of all eight IGN municipality polygons and four CAOP2025 Portuguese municipality polygons covers 297,501,253.047717 m² (99.9909%) of the pinned 297,528,340.703454 m² gap. Its remaining 27,087.655736 m² is a valid `MultiPolygon`; full EPSG:25829 residual coordinates are preserved in each run report under `full_gap_areal_coverage_and_boundary_contacts.combined_eight_returned_ign_and_four_caop_polygons.uncovered_residual_geometry_epsg25829` for later exact partition and physical classification. CAOP2025 alone covers 294,118,246.387693 m² (98.8539%), leaving 3,410,094.315761 m². The 2018 Spanish exact 55 raw members plus CAOP2025 cover 297,101,589.459906 m² (99.8566%), leaving 426,751.243548 m². All overlays retain unmodified source shapes, invalid-member lists and operation errors; no gap closure or owner assignment is applied.

The eight selected IGN lines have 124,601.889222 m of unique total length, of which 39,039.008346 m lies inside the gap. Their intersection with the gap polygon boundary has zero linear length (reported point contacts are retained individually). These dated line observations are not polygon coverage and do not determine how the full-union residual should be divided. The limited current-reference comparison is a useful source-supported proposal for later review, but not a repaired or legally certified common seam. Water/land position, seasonal channel movement, datum/registration history, and implications for the limited-AOI pilot remain unknown; no dated physical-water source was retained.

## Source custody and licensing

The baseline at `27be77596f23304de6a720735538427e6d23e242` was pinned before source work. Its `scripts/administrative.py` changes each source URL to `simplifiedGeometryGeoJSON`, downloads that URL, and hashes those cache bytes into `data/administrative-sources.json`. Accordingly, Spain’s Atlas registry SHA `e5bfa1c3889ea763ca2bb82c7f1e8ff9eff715dcb99ce405293a03de7ac85862` is the whole 18,613,175-byte `_simplified.geojson` file at geoBoundaries commit `9469f09592ced973a3448cf66b6100b741b64c0d`. Its exact full bytes and LFS pointer are retained. The same commit’s distinct unsimplified 149,105,849-byte source hashes to `ccce612ee6275d91e2d2fcccf7912087dcc72377abec6c8e20c65089ecb48564`; it is preserved as five contiguous raw-byte partitions for native member crosswalk and detail. This resolves the apparent checksum discrepancy without substituting the raw file for the Atlas input.

The same importer rule explains Portugal: its registry SHA `f7a9143190715b85812b03617adc4879898b8c6a6789b9c9732c9705ea6c21ac` identifies the 387,331-byte simplified source, while the distinct unsimplified 415,110-byte file hashes to `a02fd52278e5e300a19949450e793812fe76d78664c0a896bb3c5ebda7f79f9e`. Both are preserved with source records, commit-pinned LFS pointers, and byte receipts. The provider identifies Spain’s geoBoundaries release as CC BY 4.0 and Portugal’s as CC0 1.0; see the preserved metadata/source records and upstream [geoBoundaries repository](https://github.com/wmgeolab/geoBoundaries).

Four full native feature responses from DGT’s [CAOP2025 `municipios` OGC API](https://ogcapi.dgterritorio.gov.pt/collections/municipios?f=json), collection/queryables metadata, and four exact municipality IDs are preserved. DGT open-data reuse terms are [CC BY 4.0](https://www.dgterritorio.gov.pt/dados-abertos); its [CAOP product page](https://www.dgterritorio.gov.pt/atividades/cartografia/cartografia-tematica/caop?language=pt) describes the administrative cartographic role and records approval on 2026-01-28. Ten full direct IGN line-item responses, the separate `administrativeunit` polygon collection/queryables and eight complete direct municipality items, and their receipts are preserved from the official [IGN OGC API](https://api-features.ign.es/collections/administrativeboundary?f=json). Its linked [IGN reuse terms](https://www.ign.es/resources/licencia/Condiciones_licenciaUso_IGN.pdf) provide CC BY 4.0 reuse with attribution. The 136,542,585-byte `administrativeunit` bbox response is retained losslessly as five contiguous, independently gzip-compressed byte partitions under `sources/official-api-responses/ign-administrativeunit-bbox-discovery-partitions/`; decompression and concatenation reproduce whole-response SHA-256 `112b21ea6e3afd1503558bde7a4c771378ed458dd1f41dd8a6021a17205704f0`. This bbox selects complete returned features and does not clip their geometries; it is discovery, not a national export. Each response’s route, retrieval time, status, length, and hash are in its receipt.

The DGT national GPKG and CNIG national SHP/GML listings were not downloaded. Direct complete API items, rather than bounded extracts or reconstructed national files, are the retained official geometry. No source file was simplified, clipped, repaired, or replaced for this comparison. Per-file and total evidence-byte limits are recorded in the evidence manifest.

## Reproduction and limits

`scripts/reproduce-comparison.py` verifies exact pinned baseline files, source receipts, API item identities, and hashes before measuring unchanged geometries. It uses CRS84 longitude/latitude inputs projected to ETRS89 / UTM zone 29N (`EPSG:25829`) for metric measurements. It applies direct GEOS operations only; there is no snap, buffer, make-valid, nearest-owner assignment, or fill. Invalidity and operation failures are recorded rather than repaired away.

`scripts/validate-measurement-controls.py` exercises the same overlay function with two known EPSG:25829 rectangle cases. The positive case covers half of a 10,000 m² gap and verifies the 5,000 m² covered area, 5,000 m² residual, 0.5 fraction, and 150 m linear boundary contact after the test shapes are represented in CRS84 and passed through the production projection. The disjoint negative case verifies zero covered area/contact and the full 10,000 m² residual. It also checks that the two final complete reports have identical bytes. `validation/` retains the actual results. Source retrieval/crosswalk limits are documented separately and are not certified by geometry controls.

The final two complete runs used committed analysis `992cd13dfbc74af7669029c4104af390993e5471` and analysis SHA-256 `62fad3ced494623fa7b3b6c790d94e1b3d5103c6b8361c866725bd02e92ad215`. `outputs/run-09/report.json` and `outputs/run-10/report.json` compare byte-for-byte; each has SHA-256 `4f52d5ef455ae24e4ec7d0067567e6498e7407a0244a08622c3e2793ed0ad5a0`. Earlier trial outputs, including the seven-polygon run, remain diagnostic history and are not the final pair. The detailed input inventory, complete query/item receipts, full-gap coverage and residual coordinates, line-contact components, environment versions, and factual limits are in the reports and `evidence-quality.json`.
