# BC remainder audit reproduction repair — issue #667

This packet repairs and reproduces the ten-Census-Division, 335-Census-Subdivision source-only work in #609 / PR #658. It preserves all original #609 bytes and results. It does not propose boundary edits, approve the regional branch, or authorize imports.

## Immutable inputs and retained source evidence

`input-baseline.json` pins the original Git baseline `24629e5918a144a1979db80ba7012baea42036e7`, all 49 tracked files in the #609 packet and #485 inputs read by the audit, the acquisition-receipt bytes, and the source files’ raw and decompressed hashes. The input receipt is pinned as an ordinary input; it is not treated as the authority for its own contents. There are 32 retained source responses. The repair verifies all originals and receipt relationships before it computes results.

Three source files exceed the evidence reviewer’s 32 MiB per-file limit: the original Statistics Canada CD and CSD GeoJSON responses (38,880,150 and 42,765,402 bytes) and the complete geoBoundaries source (42,649,707 bytes). `extract_inputs.py` verifies full Git blobs and byte streams, then creates 143 bounded derivatives (62 MB total) for the assigned CSDs, BC CD neighbor screening, parent-chain context, and geoBoundaries candidates. The oversized CD is divided only at original MultiPolygon component boundaries and reassembled before measurement. The geoBoundaries candidates are a complete coordinate-bbox superset, not a claim of exact spatial intersection. `extract_complete_geoboundaries.py` also preserves all 5,162 geoBoundaries features in source order across lossless gzip chunks; `reproduce.py` reconstructs the full collection and checks exact feature equality against the pinned source blob. Hashes and partition counts are in the extraction receipts.

The ten native CDUID subjects are checked through a limited prior-evidence inventory: the ancestor #485 `cd-assessments.json` `/exact_subjects` roster is pinned at commit `24629e5918a144a1979db80ba7012baea42036e7`, and `source-subject-registry.geojson` is a candidate identity-only projection with null geometries. This confirms agreement with retained prior evidence; it does not independently verify membership in the original Statistics Canada source or the CD geometries. The original 38,880,150-byte CD source remains above the shared 32 MiB input limit, so this registry does not certify source extraction, boundary truth, or regional approval.

The source catalog in the original #609 packet records the canonical references, vintage, retrieval times, licenses and limitations: Statistics Canada 2021 Census geography (Open Licence Canada); geoBoundaries Canada ADM3 2016 (the upstream ODbL/Statistics Canada Open License metadata discrepancy is retained); BC legal regional-district, electoral-area and municipality services (Open Government Licence–BC); and NRCan Aboriginal Lands of Canada Legislative Boundaries (Open Government Licence–Canada). Inherited 2021 Population Centres and GNBC populated-place evidence retains its #485 citations and license context. Statistical units, cartographic matches and source-member IDs do not establish legal equivalence or political ownership. NRCan’s source excludes Indian Settlements and Communities.

## Reproduction, differences, and controls

`reproduce.py` checks pinned original and derived bytes, loads the original audit algorithm from the pinned #609 Git blob, and directs writes only to a new explicit destination inside this issue’s owned path. Default/check mode is read-only; an existing destination is rejected. The old `member_id_map()` silently kept the last location when a geoBoundaries source-member ID appeared in multiple Atlas locations. The corrected mapping validation reports conflicts and leaves ambiguous scalar location/parent-chain assignments unset while retaining all candidate locations and historical assignments in `mapping-differences.json`.

Two separate output directories produced byte-identical results for all ten CDs and 335 CSD rows. All numeric and geometric measurements otherwise match the original outputs. The pinned #485 assessment has 733 distinct source-member IDs: 649 map to one Atlas location; 84 map to two or more. This affects 426 CSD candidate rows and 148 CD source-roster rows. There are no other CSV or JSON differences. The exact source IDs, rows, old assignments and parent chains, null reproduced scalar assignments, and JSON pointers are preserved in `mapping-differences.json` and summarized by `reproduction-receipt.json`. These collisions establish an input ambiguity, not which Atlas location is geographically or politically correct. A bounded follow-up should decide how the data model represents legitimate one-to-many source associations before any location attribution is imported.

`control_tests.py` records passing negative controls for a changed parent assessment, changed acquired layer, missing input, conflicting assignment, and attempted output overwrite. Original #609 output hashes are unchanged before and after. `compare_reproductions.py` compares both runs, original output hashes, source rows and parent chains. `evidence-controls.py` binds the successful positive, negative and repeatability receipts and summarizes metric values. `evidence-quality.json` identifies all ten assigned CDs and pins source bytes, subjects, methods, measurements, outputs and limits. Run the reproduction with Python 3 and the isolated environment containing `shapely==2.1.2` and `pyproj==3.7.2`; no repository dependency or production code is changed. The measurement method and CRS are inherited from the original #609 audit, not a new factual or legal boundary validation.

All original #609 unresolved findings, administrative remainders, neighboring-CD observations, and inter-region coordination notes remain in place. The packet documents source and reproducibility evidence only; engineering must integrate accepted findings and validate/publish the complete regional branch before attribute research imports are eligible.
